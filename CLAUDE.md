# SAA-C03 Trainer — заметки для будущих сессий

Тренажёр и учебник по AWS SAA-C03. Ванильный JS без сборщика, работает по `file://`
и с любого статического хостинга. Исходный HANDOFF с постановкой задачи — `HANDOFF.md`.

## Правила работы с данными

- `data/questions.json` — **сборочный артефакт**, руками не править. Любая правка
  ключа, спорности, дефекта или экспоната идёт в `data/overlay.json`, после чего
  пайплайн пересобирает банк.
- `scripts/parse.py` заточен под конкретный дамп (`data/raw.txt`, 1019 вопросов).
  Менять его под другой дамп только со сверкой на этом.
- `answer_original` и `fix_note` не удалять: это доказательная часть аудита.
- Разметка доменов (`dom`) отражает содержание вопросов, а не blueprint. Не подгонять
  её под проценты экзамена — выборка экзамена и так строится по весам из `meta.json`.
- Всё, что правила `classify.py` не определили сильными маркерами (347 вопросов),
  прочитано и размечено вручную в `data/dom-overrides.json`:
  `{"id": {"dom": "SEC", "why": "короткое обоснование"}}`. Обоснование обязательно —
  `validate.py` требует его и не пропускает сборку, если в банке остались вопросы
  с `dom_conf` weak или fallback. Новые вопросы без сильных маркеров разбирать так же
  вручную, а не подкручивать правила ради одного случая.
- Принцип разметки: домен определяется требованием, которое отсекает неверные
  варианты (дискриминатором), а не темой вопроса и не мотивом из преамбулы. Доступ
  к S3 через endpoint ради изоляции — SEC, тот же endpoint ради экономии на NAT — COST.
- Правила разрешения спорных случаев (применены при перепроверке 2026-08-25):
  - выбор типа Storage Gateway, класса FSx, EFS против EBS решается протоколом и
    характером доступа — это PERF; COST только когда решает класс хранения или
    прямая формулировка про стоимость;
  - организационный guardrail (SCP, Control Tower, Config, инвентаризация) — SEC,
    даже если мотив в преамбуле денежный; теги ради распределения затрат — COST;
  - вынос состояния из инстансов (сессии, общие документы) — RES; выбор общего
    хранилища ради скорости, роста или согласованности — PERF;
  - выбор вычислений под длительность и профиль задачи — PERF; гарантия ёмкости
    и переживание отказа зоны — RES.
- Счётчики `count` в `data/meta.json` пересчитывает `apply-audit.py`; руками не трогать.

## Порядок пересборки

```bash
bash scripts/build.sh    # parse -> classify -> apply-audit -> theory -> web -> validate
```

`web/data/bank.js` и `web/data/theory.js` — генерируются, вручную не редактировать.

## Учебник

- одна глава = `docs/<id>.md` с frontmatter `id`, `title`, `order`, `svc`;
- `svc` должен совпадать с именами сервисов из `scripts/classify.py`, иначе глава
  не свяжется с вопросами;
- объём главы 150–400 строк, обязательные блоки: «что спрашивают на экзамене»,
  сравнительные таблицы, «числа, которые надо помнить», мини-практикум, «аудит банка»;
- ссылка на вопросы внутри текста — `{{q:110,239}}`, сборка превращает её в кликабельный
  переход к тренировке по этим id;
- markdown конвертируется в HTML на этапе сборки (`scripts/build-theory.py`), поэтому
  в приложении нет markdown-парсера. Поддерживается подмножество: заголовки, списки,
  таблицы, код, цитаты, ссылки, `**жирный**`, `*курсив*`, `` `код` ``.

## Приложение

- `web/js/storage.js` — localStorage, ключ `saa-c03:v1`;
- `web/js/quiz.js` — карточка вопроса, тренировка, экзамен;
- `web/js/theory.js` — учебник;
- `web/js/app.js` — роутинг и вкладки;
- никаких ES-модулей и `fetch` локальных файлов: то и другое ломается на `file://`.

## Сайт

- `saa.maks.top` собирается из ветки `main` workflow-ом `.github/workflows/pages.yml`;
- путь к картинкам-экспонатам берётся из `window.SAA_CONFIG.exhibits`: локально
  `web/config.js` даёт `../images/exhibits/`, сборка сайта подменяет его на
  `images/exhibits/`. Хардкодить путь в `quiz.js` обратно нельзя — сломается одна
  из двух раскладок;
- `robots.txt` в сборке запрещает индексацию: содержимое банка это сторонний дамп.

## Чего не делать в этой версии

Аккаунтов, синхронизации, серверной части и APK нет и не планируется на первом этапе.
Внешние CDN и фреймворки не подключать — приложение должно работать офлайн.
