# SAA-C03 trainer — handoff для Claude Code

Проект: тренажёр по AWS Certified Solutions Architect Associate (SAA-C03) с банком
вопросов и учебными материалами. Аналог по духу `NickelFace/ccna-trainer`, но со своей
структурой, а не копией.

Автор проекта: Maks (GitHub NickelFace). Язык интерфейса приложения: английский для
терминов и текста вопросов, объяснения и учебник на русском.

## 3. Схема записи вопроса

```json
{
  "id": 96,
  "question": "текст вопроса, переводы строк сохранены",
  "options": [{"l": "A", "t": "текст варианта"}],
  "answer": "C",
  "multi": false,
  "dom": "SEC",
  "dom_conf": "strong",
  "svc": ["EC2", "IAM"],
  "exhibits": ["q96.png"]
}
```

Необязательные поля:

- `answer_original` и `fix_note` — если ключ дампа был исправлен при аудите (18 вопросов).
  В `answer` лежит исправленный ответ, в `answer_original` то, что было в PDF.
- `disputed_alt` и `disputed_note` — спорные вопросы (15). Ключ сохранён, альтернатива и
  аргумент записаны рядом. В приложении такой вопрос надо показывать с пометкой.
- `defect` — дефект исходного PDF (#868, отсутствует вариант A).
- `note` — исправленная буква варианта (#125, #756).
- у `options` может быть `img` — вариант ответа является картинкой (только #477).

Значения `dom`: `SEC`, `RES`, `PERF`, `COST`.
Значения `dom_conf`: `strong` (672), `weak` (139), `fallback` (208).

## 6. Задача: структура репозитория

```
saa-trainer/
  README.md
  data/
    questions.json          банк (готов)
    meta.json               домены, веса, версия банка, статистика
    theory/                 конспекты в json для приложения
      s3.json, ec2.json, ...
  docs/                     те же конспекты в markdown для чтения на GitHub
  images/exhibits/          картинки вопросов
  web/
    index.html
    css/app.css
    js/
      app.js                состояние и роутинг
      quiz.js               логика тренировки и экзамена
      theory.js             просмотр учебника
      storage.js            прогресс в localStorage
  scripts/
    parse.py                PDF -> questions.json
    classify.py             разметка доменов и сервисов
    build-theory.py         markdown -> data/theory/*.json
```

Осознанные отличия от ccna-trainer: теория здесь первична и связана с вопросами через
поле `svc`, а не лежит отдельной вкладкой. Мобильная обёртка (Capacitor) не делается на
первом этапе, сначала работающий веб.

## 7. Задача: учебные материалы

Конспекты пишутся по сервисам и темам, а не по доменам, потому что вопросы дампа
привязаны к сервисам. Ориентировочный список из 22 глав, отсортирован по частоте в банке:

1. S3: классы хранения, lifecycle, версионирование, Object Lock, репликация, шифрование
2. EC2: типы инстансов, модели покупки (On-Demand, RI, Savings Plans, Spot), placement groups
3. Auto Scaling и балансировщики: ALB, NLB, GWLB, политики масштабирования
4. VPC: подсети, маршрутизация, NAT, endpoints (gateway против interface), peering
5. IAM: политики, роли, кросс-аккаунт, Identity Center, permission boundaries, SCP
6. Шифрование: KMS, ключи (managed, customer managed, multi-Region), SSE-S3/KMS/C, Bucket Key
7. RDS: Multi-AZ instance против Multi-AZ cluster, read replicas, Proxy, бэкапы
8. Aurora: типы хранилища, endpoints (writer, reader, custom), Serverless, Global Database
9. DynamoDB: capacity modes, GSI/LSI, Streams, DAX, global tables
10. Lambda: лимиты, конкурентность, function URLs, layers, VPC-доступ
11. Интеграция: SQS (standard против FIFO), SNS, EventBridge, Step Functions, MQ
12. Хранилища файлов: EFS, FSx (Windows, Lustre, ONTAP, OpenZFS), выбор по протоколу
13. EBS: типы томов, лимиты IOPS, снапшоты, шифрование
14. Гибрид и миграция: Direct Connect, Site-to-Site VPN, Transit Gateway, PrivateLink
15. Перенос данных: DataSync, Storage Gateway (три типа), Snow Family, Transfer Family
16. Контент и edge: CloudFront, OAC, signed URL и cookies, Global Accelerator
17. Route 53: типы записей и все политики маршрутизации, health checks
18. Контейнеры: ECS, EKS, Fargate, IRSA, capacity providers
19. Аналитика: Kinesis, Glue, Athena, Redshift, EMR, OpenSearch, QuickSight
20. Безопасность периметра: WAF, Shield, GuardDuty, Macie, Inspector, Network Firewall
21. Управление: Organizations, Control Tower, Config, CloudTrail, Systems Manager, Backup
22. Стоимость: Cost Explorer, Budgets, Compute Optimizer, Trusted Advisor, теги распределения

Требования к главе:

- пишется по-русски, термины и имена сервисов на английском
- обязательный блок "что спрашивают на экзамене" с типовыми ловушками
- обязательный блок сравнения там, где выбор между похожими сервисами
- ссылки на конкретные id вопросов банка через `svc`, чтобы можно было сразу порешать
- без воды и без пересказа документации целиком, объём 150 до 400 строк на главу

Писать по одной главе за раз, начиная с S3, и после каждой прогонять сборку в json.

## 8. Задача: приложение

Минимум для первой версии:

- Режим Тренировка: фильтры по домену, сервису, статусу (все, ошибочные, отмеченные),
  мгновенный показ правильного ответа и разбора
- Режим Экзамен: 65 вопросов по весам blueprint, таймер 130 минут, результат по доменам
- Разбор вопроса: правильный ответ, объяснение, ссылка на главу учебника по `svc`,
  для исправленных вопросов показ `fix_note`, для спорных предупреждение с `disputed_alt`
- Прогресс в localStorage: пройденные, ошибочные, отмеченные, история попыток экзамена
- Экспонаты: картинка из `images/exhibits`, для #477 картинки в самих вариантах
- Учебник: список глав, поиск, чтение, переход к вопросам по теме

Технически: чистый JS без сборщика, чтобы открывалось с файловой системы и с GitHub Pages.
Один банк на 1.2 МБ грузить целиком нормально, но при первом рендере резать на чанки.

Явно не делать в первой версии: аккаунты, синхронизацию, серверную часть, APK.

## 9. Критерии готовности

1. `python3 scripts/parse.py && python3 scripts/classify.py` отрабатывают на чистом клоне
2. В банке 1019 вопросов, у каждого непустые `answer`, `dom`, `svc`
3. Экзаменационная выборка даёт распределение 20/17/15/13 по доменам
4. Все 22 главы существуют и в markdown, и в json, ни одна не пустая
5. Приложение открывается локально без сервера и переживает перезагрузку страницы
   с сохранением прогресса
6. Для всех 18 исправленных и 15 спорных вопросов в интерфейсе виден соответствующий блок
