# Гибридные подключения

Задача — соединить локальную сеть с AWS так, чтобы выполнялись требования по
пропускной способности, стабильности задержки, приватности и стоимости. Четыре
кирпича: Site-to-Site VPN, Direct Connect, Transit Gateway и PrivateLink.

## Site-to-Site VPN

IPSec-туннель через интернет между customer gateway и virtual private gateway или
Transit Gateway. Всегда два туннеля в разные endpoint AWS для отказоустойчивости.

- поднимается за минуты, оплата почасовая плюс трафик;
- пропускная способность одного туннеля около 1.25 Гбит/с, масштабируется ECMP через
  Transit Gateway;
- задержка и джиттер зависят от интернета — предсказуемости нет;
- шифрование встроено;
- типовые роли: быстрый старт, резерв для Direct Connect, подключение филиалов.

Accelerated Site-to-Site VPN пускает туннель через сеть Global Accelerator, снижая
влияние публичного интернета.

## Direct Connect

Выделенное физическое подключение из вашего оборудования в точку присутствия AWS:
1, 10, 100 Гбит/с (dedicated) или суб-скорости через партнёра (hosted).

- предсказуемая задержка и пропускная способность, дешевле исходящий трафик;
- разворачивается недели или месяцы — на «нужно за два дня» это неверный ответ;
- сам по себе не шифрует: при требовании шифрования поверх DX запускают IPSec VPN
  или используют MACsec на поддерживаемых портах;
- типы виртуальных интерфейсов: private VIF — в VPC через VGW, transit VIF — в
  Transit Gateway, public VIF — к публичным endpoint AWS (S3, DynamoDB) в обход
  интернета;
- отказоустойчивость: два подключения в разных точках присутствия, либо DX плюс VPN
  как резерв (стандартный дешёвый вариант), либо Direct Connect SiteLink между
  своими площадками;
- Link Aggregation Group объединяет порты в один логический канал.

## Что выбрать

| Требование | Ответ |
|---|---|
| Соединить офис с VPC за один день | Site-to-Site VPN |
| Стабильная задержка для чувствительного приложения | Direct Connect |
| Максимально дёшево при большом исходящем трафике | Direct Connect |
| Быстро и с шифрованием, бюджет ограничен | VPN |
| DX уже есть, нужен резерв | VPN как backup |
| Соединить 50 VPC и локальную сеть | Transit Gateway |
| Дать партнёру доступ только к одному приложению | PrivateLink |

## Transit Gateway

Региональный хаб: VPC, VPN, Direct Connect gateway и другие TGW подключаются
вложениями (attachments), маршрутизация описывается таблицами. Возможности, которые
проверяют: транзитивная маршрутизация (в отличие от peering), сегментация окружений
разными таблицами маршрутов, межрегиональный peering, multicast, централизованный
выход в интернет и централизованная инспекция трафика через Network Firewall или GWLB.

Стоимость: почасовая плата за каждое вложение плюс плата за обработанный трафик,
поэтому для двух VPC peering обычно дешевле.

## PrivateLink

Interface endpoint с приватным IP в вашей подсети, ведущий к сервису AWS, партнёра
или к вашему собственному сервису за NLB (endpoint service). Свойства, за которые его
выбирают: сети не соединяются, CIDR могут пересекаться, трафик односторонний
(потребитель к поставщику), доступ ограничивается endpoint policy.

Классический сценарий: SaaS-компания даёт клиентам доступ к своему API без VPN и
peering; или крупная организация публикует внутренний сервис для сотен аккаунтов.

## Гибридный DNS

Чтобы локальные серверы резолвили приватные зоны AWS, создают Route 53 Resolver
inbound endpoint; чтобы ресурсы AWS резолвили корпоративные зоны — outbound endpoint
с правилами пересылки. Правила шарятся между аккаунтами через RAM. Эта пара
эндпоинтов — стандартный ответ на «имена не резолвятся между дата-центром и облаком».

## Локальные расширения AWS

- Outposts — стойка или сервер AWS в вашем дата-центре, те же API, для требований
  по локальности данных и задержке к локальным системам;
- Local Zones — площадки AWS в крупных городах для задержки в единицы миллисекунд;
- Wavelength — зоны внутри сетей операторов 5G;
- Storage Gateway и DataSync — см. главу про перенос данных;
- ECS Anywhere и EKS Anywhere запускают контейнерные оркестраторы на своём железе.

## Что спрашивают на экзамене

1. «Нужна стабильная задержка и высокая пропускная способность в дата-центр» — Direct
   Connect, при требовании шифрования — плюс VPN.
2. «DX уже строится, но подключение нужно сейчас» — временно VPN.
3. «Соединить десятки VPC без сетки peering» — Transit Gateway.
4. «Партнёру нужен доступ только к нашему API, сети соединять нельзя» — PrivateLink.
5. «Резерв для Direct Connect с минимальными затратами» — Site-to-Site VPN.
6. «Приложение должно работать на площадке из-за требований к данным» — Outposts.
7. «Локальные серверы не видят имена RDS в VPC» — Resolver inbound endpoint.
8. «Доступ к S3 из дата-центра минуя интернет» — public VIF через Direct Connect или
   interface endpoint, выбор по стоимости и требованиям.

## Числа, которые надо помнить

- Site-to-Site VPN: всегда два туннеля, около 1.25 Гбит/с на туннель, поднимается
  за минуты;
- Direct Connect: 1, 10, 100 Гбит/с dedicated, суб-скорости hosted, срок поставки
  недели и месяцы;
- Direct Connect сам по себе не шифрует трафик;
- Transit Gateway: тысячи вложений, оплата за вложение и за обработанный трафик,
  межрегиональный peering;
- PrivateLink: односторонний доступ потребитель → поставщик, CIDR могут пересекаться;
- VPC peering: не транзитивен, CIDR пересекаться не должны.

## Как читать формулировку

| В тексте вопроса | Ответ |
|---|---|
| «consistent latency, dedicated bandwidth» | Direct Connect |
| «connect quickly, encrypted, low cost» | Site-to-Site VPN |
| «backup for Direct Connect» | VPN как резервный путь |
| «hundreds of VPCs, central routing» | Transit Gateway |
| «expose one service to customers without connecting networks» | PrivateLink |
| «overlapping CIDR ranges after a merger» | PrivateLink или NAT, не peering |
| «resolve on-premises names from AWS» | Resolver outbound endpoint с правилами |
| «run AWS services in our data center» | Outposts |

## Порядок разбора гибридного вопроса

1. Что соединяем: сеть с сетью (VPN, DX, TGW) или потребителя с сервисом (PrivateLink).
2. Срок: дни — VPN, месяцы допустимы — Direct Connect.
3. Требование шифрования: DX без VPN его не даёт.
4. Масштаб: два-три VPC — peering, десятки — Transit Gateway.
5. Пересечение адресов: если CIDR совпадают, маршрутизация невозможна в принципе.
6. Резервирование: два DX в разных точках присутствия, либо DX плюс VPN.

## Мини-практикум

**1.** Компания переносит ERP в AWS и требует стабильной задержки к дата-центру,
запуск через полгода.
→ Direct Connect; на время строительства — Site-to-Site VPN.

**2.** Требование аудита: трафик между дата-центром и AWS должен быть зашифрован,
а канал — выделенный.
→ Direct Connect плюс IPSec VPN поверх него (или MACsec на поддерживаемых портах).

**3.** В организации 40 VPC в двух регионах и два дата-центра.
→ Transit Gateway в каждом регионе, межрегиональный peering, вложения для VPN и DX.

**4.** SaaS-поставщик даёт доступ к своему API, соединять сети нельзя, адресация
пересекается.
→ PrivateLink: interface endpoint в вашей VPC, маршрутизация между сетями не нужна.
