# Контент и edge

Edge-сеть AWS решает три задачи: приблизить контент к пользователю, снять нагрузку с
origin и дать стабильную сетевую доставку через магистраль AWS вместо публичного
интернета.

## CloudFront

CDN поверх сотен точек присутствия. Работает с HTTP и HTTPS, кэширует ответы, умеет
сжимать, подписывать и обрабатывать запросы функциями на краю.

Origin: S3 (через Origin Access Control), ALB, EC2, API Gateway, любой публичный HTTP
сервер, в том числе вне AWS. Origin group даёт failover на резервный источник по кодам
ошибок — простой способ выполнить требование отказоустойчивости раздачи.

Ключевые механики:

- cache policy определяет ключ кэша (какие заголовки, cookie и query участвуют) и TTL;
  origin request policy определяет, что пересылается на origin;
- инвалидация удаляет объекты из кэша досрочно; версионирование имён файлов
  (`app.v2.js`) дешевле и надёжнее массовых инвалидаций;
- signed URL и signed cookies закрывают платный контент: URL — один объект, cookies —
  набор объектов;
- Origin Access Control (OAC, наследник OAI) даёт CloudFront доступ к приватному
  бакету, а бакет остаётся закрытым для интернета;
- поле Geo restriction блокирует страны на уровне CDN;
- сертификат для собственного домена выпускается в ACM в регионе us-east-1
  независимо от того, где находится origin;
- WAF цепляется к дистрибуции, Shield Advanced защищает от объёмных атак;
- логи: стандартные access logs в S3 и real-time logs в Kinesis.

Функции на краю:

| | CloudFront Functions | Lambda@Edge |
|---|---|---|
| Язык | JavaScript | Node.js, Python |
| Время | менее 1 мс | до 5 или 30 секунд |
| События | viewer request/response | все четыре, включая origin |
| Доступ к сети и телу запроса | нет | да |
| Цена | очень низкая | выше |

Простая подмена заголовков, редиректы, нормализация ключа кэша — CloudFront Functions;
обращение к внешнему API, A/B-логика, работа с телом — Lambda@Edge.

## Global Accelerator

Два статических anycast-адреса, трафик заходит в ближайшую точку присутствия и дальше
идёт по магистрали AWS до ближайшего здорового endpoint (ALB, NLB, EC2, Elastic IP).
Работает с TCP и UDP, поэтому подходит там, где CloudFront бессилен: игры, VoIP, IoT,
собственные протоколы.

Свойства, за которые его выбирают: статические IP для белых списков, быстрый
межрегиональный failover по health checks (секунды), взвешенное распределение трафика
по регионам, клиентская привязка (client affinity).

## CloudFront против Global Accelerator

| Требование | Ответ |
|---|---|
| Кэширование HTTP-контента | CloudFront |
| Статические IP-адреса | Global Accelerator |
| UDP или произвольный TCP | Global Accelerator |
| Раздача видео и статики | CloudFront |
| Мгновенное переключение между регионами | Global Accelerator |
| Снижение нагрузки на origin | CloudFront |
| Динамический API с высокой задержкой из-за расстояния | оба варианта возможны: CloudFront терминирует TLS ближе и держит соединение до origin, GA сокращает путь по магистрали |

## Стоимость

CloudFront экономит на исходящем трафике: отдача из кэша дешевле, чем из S3 или EC2,
плюс отсутствует плата за трафик от origin при попадании в кэш. Класс цены (Price Class)
ограничивает набор регионов присутствия и снижает цену, если аудитория локальна.
Global Accelerator оплачивается почасово плюс премия за переданные данные.

## Типовые схемы

- Статика в S3 с OAC + динамика на ALB как второй origin, маршрутизация по path-pattern.
- API Gateway за CloudFront с кэшированием GET и WAF на дистрибуции.
- Видео: S3 как origin, signed cookies для подписчиков, MediaConvert для перекодирования.
- Мультирегиональная отказоустойчивость: Route 53 failover или Global Accelerator
  перед региональными балансировщиками.

## Что спрашивают на экзамене

1. «Пользователи по всему миру жалуются на скорость загрузки картинок» — CloudFront.
2. «Бакет должен оставаться приватным, но контент раздаётся» — OAC.
3. «Нужны фиксированные IP для партнёрского firewall» — Global Accelerator или NLB.
4. «Игровой сервер по UDP с игроками в трёх регионах» — Global Accelerator.
5. «Платный контент доступен только подписчикам на 24 часа» — signed URL или cookies.
6. «Заблокировать доступ из отдельных стран» — geo restriction (или WAF-правило).
7. «Кэш отдаёт старую версию сайта после деплоя» — инвалидация или версионирование имён.
8. «Сертификат не появляется в списке CloudFront» — он выпущен не в us-east-1.

## Числа, которые надо помнить

- сотни точек присутствия, кэш по регионам плюс региональные edge-кэши;
- TTL задаётся политикой кэша и заголовками origin, по умолчанию 24 часа;
- инвалидация: первые 1000 путей в месяц бесплатны, дальше платно;
- CloudFront Functions — менее 1 мс и только viewer-события, Lambda@Edge — до 5 секунд
  на viewer и до 30 секунд на origin-событиях;
- сертификат для собственного домена — только из ACM в us-east-1;
- Global Accelerator даёт 2 статических anycast-адреса и переключает трафик за секунды.

## Как читать формулировку

| В тексте вопроса | Ответ |
|---|---|
| «global users, static and media content» | CloudFront |
| «keep the S3 bucket private» | OAC |
| «static IP addresses for allowlisting» | Global Accelerator или NLB |
| «UDP or non-HTTP protocol» | Global Accelerator |
| «restrict content to paying subscribers» | signed URL или signed cookies |
| «block specific countries» | geo restriction или WAF |
| «fast failover between Regions» | Global Accelerator или Route 53 health checks |
| «reduce load and egress cost from origin» | CloudFront |

## Проверка кэша при разборе задачи

Кэш работает, если ключ кэша стабилен: лишние заголовки, cookie и query-параметры в
ключе фрагментируют кэш и снижают hit rate до нуля. Признаки в вариантах ответа:
«forward all headers and cookies» — почти всегда ухудшение, «cache policy with only
required query strings» — улучшение. Динамический контент тоже выигрывает от
CloudFront: TLS терминируется рядом с пользователем, а до origin идёт постоянное
соединение по магистрали AWS, что сокращает время установления сессии.

## Мини-практикум

**1.** Сайт на ALB в eu-central-1, половина пользователей в Азии жалуется на медленную
загрузку картинок.
→ CloudFront перед ALB и S3: кэш ближе к пользователю, TLS терминируется на краю.

**2.** Требуется отдавать файлы из приватного бакета только через CDN.
→ Origin Access Control плюс bucket policy, разрешающая доступ только дистрибуции.

**3.** Партнёр требует список статических IP-адресов для белого списка, приложение
работает по TCP.
→ Global Accelerator: два статических anycast-адреса и переключение по health checks.

**4.** После деплоя пользователи видят старую версию JavaScript.
→ Версионировать имена файлов или инвалидировать пути; при этом привести в порядок
cache policy.
