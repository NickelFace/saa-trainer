# Route 53

Управляемый DNS с интеграцией в сервисы AWS, health checks и семью политиками
маршрутизации. На экзамене используется как инструмент отказоустойчивости и глобального
распределения трафика, а не только как хостинг зоны.

## Зоны и записи

- public hosted zone обслуживает имена в интернете, private hosted zone — внутри
  указанных VPC;
- типы записей: A, AAAA, CNAME, MX, TXT, NS, SRV, CAA, PTR;
- alias-запись — расширение AWS: указывает на ALB, NLB, CloudFront, S3 website,
  API Gateway, Global Accelerator, другую запись в той же зоне. Бесплатна, работает
  для корня домена (zone apex), где CNAME запрещён — это разница, которую проверяют
  почти в каждом наборе;
- TTL определяет, как быстро клиенты увидят изменение: перед миграцией TTL понижают.

## Политики маршрутизации

| Политика | Что делает | Типовое требование |
|---|---|---|
| Simple | одна запись, без health check | базовый случай |
| Weighted | распределение по весам | canary-выкат, миграция 10/90 |
| Latency-based | ближайший по сетевой задержке регион | «максимальная производительность для глобальных пользователей» |
| Failover | активный-пассивный по health check | DR-схема с резервным сайтом |
| Geolocation | по стране или континенту пользователя | локализация контента, юридические ограничения |
| Geoproximity | по расстоянию с возможностью смещения (bias) | плавный перенос трафика между регионами |
| Multivalue answer | до 8 здоровых записей в ответе | простая балансировка без балансировщика |

Различие latency и geolocation — постоянная ловушка: «наименьшая задержка» это latency,
«пользователи из Германии должны видеть немецкий сайт» это geolocation.

## Health checks

Три вида: проверка endpoint по HTTP/HTTPS/TCP, проверка состояния других проверок
(calculated) и проверка тревоги CloudWatch. Используются в failover, multivalue и в
связке с DNS-записями любых политик. Health check с CloudWatch alarm — способ следить
за приватными ресурсами, которые нельзя опрашивать из интернета.

Схема активный-активный между регионами: latency-политика с health check в каждом
регионе; активный-пассивный: failover-политика, primary с health check и secondary.
CloudFront в такой схеме не выполняет проверку здоровья origin между регионами —
это делает Route 53.

## Регистрация доменов и DNSSEC

Route 53 может быть регистратором домена и хостингом зоны одновременно, но это
независимые функции: домен у стороннего регистратора спокойно обслуживается зоной в
Route 53 через смену NS-записей. DNSSEC подписывает зону и защищает от подмены ответов;
включается на public hosted zone с ключом в KMS.

## Resolver и гибридный DNS

Route 53 Resolver отвечает за разрешение имён внутри VPC. Inbound endpoint принимает
запросы из локальной сети, outbound endpoint с правилами пересылает запросы в
корпоративные DNS. Правила шарятся через RAM между аккаунтами. Resolver DNS Firewall
блокирует обращения к вредоносным доменам и служит частью защиты от эксфильтрации.

## Схемы отказоустойчивости

| Задача | Конструкция |
|---|---|
| Резервный статический сайт на время аварии | failover на S3 website или CloudFront |
| Балансировка между регионами по производительности | latency + health checks |
| Постепенный перенос на новую платформу | weighted, вес меняется во времени |
| Требования локализации данных | geolocation |
| Простая балансировка без ELB | multivalue answer |

## Что спрашивают на экзамене

1. «Корень домена должен указывать на ALB» — alias-запись, CNAME на apex невозможен.
2. «Пользователи должны попадать в ближайший по скорости регион» — latency-based.
3. «При отказе основного региона переключиться на резервный» — failover с health check.
4. «Показывать разный контент по странам» — geolocation.
5. «Выкатить новую версию на 5 процентов трафика» — weighted.
6. «Локальные серверы должны резолвить private hosted zone» — Resolver inbound endpoint.
7. «Домен зарегистрирован у стороннего регистратора» — оставить регистратора, сменить
   NS на Route 53.
8. «Нужно быстро переключить трафик, но кэш DNS у клиентов долгий» — заранее снизить
   TTL или использовать Global Accelerator со статическими IP.

## Числа, которые надо помнить

- health check опрашивает endpoint из нескольких точек мира, интервал 30 или 10 секунд,
  переключение после трёх последовательных отказов;
- multivalue answer возвращает до 8 здоровых записей;
- alias бесплатен, обычные запросы тарифицируются за миллион;
- private hosted zone связывается с несколькими VPC, в том числе в разных аккаунтах;
- TTL по умолчанию 300 секунд для новых записей, alias наследует TTL цели;
- Resolver endpoints стоят почасово за каждый IP-адрес.

## Как читать формулировку

| В тексте вопроса | Ответ |
|---|---|
| «apex domain must point to a load balancer» | alias-запись |
| «lowest latency for global users» | latency-based routing |
| «active-passive disaster recovery» | failover routing с health check |
| «serve different content per country» | geolocation |
| «shift 10 percent of traffic to the new stack» | weighted routing |
| «on-premises servers must resolve AWS private names» | Resolver inbound endpoint |
| «block malicious domain lookups» | Route 53 Resolver DNS Firewall |
| «need static IPs and instant failover» | Global Accelerator, а не DNS |

## Мультирегиональные схемы целиком

Активный-пассивный: основной регион с приложением, резервный в состоянии pilot light
или warm standby, Route 53 failover переключает по health check. RTO определяется
временем разворачивания резерва и TTL записи.

Активный-активный: оба региона обслуживают трафик, latency-политика с health checks
распределяет пользователей, данные синхронизируются через Aurora Global Database,
DynamoDB global tables или репликацию S3. Такая схема дороже, но RTO измеряется
минутами и меньше.

Отдельный приём: страница обслуживания на S3 как secondary в failover-записи —
дешёвый способ показать пользователям корректное сообщение вместо ошибки.

## Мини-практикум

**1.** Домен example.com должен указывать на ALB, CNAME на корне не работает.
→ Alias-запись типа A на балансировщик: бесплатна и разрешена на zone apex.

**2.** Приложение развёрнуто в четырёх регионах, пользователи должны попадать в самый
быстрый.
→ Latency-based routing с health check в каждом регионе.

**3.** Основной регион упал, нужно автоматически перевести трафик на резервный.
→ Failover routing: primary с health check, secondary — резервный стек или страница
обслуживания на S3.

**4.** Локальные серверы не резолвят имена RDS из private hosted zone.
→ Route 53 Resolver inbound endpoint и пересылка запросов из корпоративного DNS.
