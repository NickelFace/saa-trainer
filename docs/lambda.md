# Lambda

Функция выполняется в ответ на событие, платите за время работы и число вызовов,
серверов нет. Типовые роли в архитектуре: обработчик событий S3, DynamoDB Streams,
SQS, EventBridge; бэкенд API за API Gateway или ALB; клей между сервисами; периодические
задачи по расписанию.

## Лимиты, которые проверяют

| Параметр | Значение |
|---|---|
| Максимальное время выполнения | 15 минут |
| Память | 128 МБ — 10 240 МБ |
| vCPU | пропорционально памяти, до 6 при максимуме |
| Размер пакета | 50 МБ zip (сжатый), 250 МБ распакованный, 10 ГБ образ контейнера |
| `/tmp` | 512 МБ — 10 240 МБ |
| Payload | 6 МБ синхронно, 256 КБ асинхронно |
| Конкурентность аккаунта | 1000 по умолчанию, поднимается через квоты |

Требование «обработка занимает больше 15 минут» автоматически выводит Lambda из ответа:
дальше идут ECS/Fargate, AWS Batch или Step Functions с разбиением на шаги.

## Модели вызова

- Синхронная (API Gateway, ALB, прямой вызов): ошибка возвращается вызывающему,
  ретраи на стороне клиента.
- Асинхронная (S3, SNS, EventBridge): встроенные две повторные попытки, затем
  destination или dead-letter queue.
- Poll-based (SQS, Kinesis, DynamoDB Streams): Lambda сама опрашивает источник,
  батчами; порядок гарантируется для FIFO и для шарда потока.

Обработка ошибок: DLQ или Lambda Destinations (успех и провал направляются в SQS, SNS,
EventBridge или другую функцию). Идемпотентность обработчика — требование, а не пожелание.

## Конкурентность

- Reserved concurrency резервирует часть общего лимита за функцией и одновременно
  ограничивает её сверху — способ защитить базу от перегрузки и не дать одной функции
  съесть весь лимит аккаунта;
- Provisioned concurrency держит инициализированные окружения наготове — ответ на
  «холодный старт недопустим», особенно для Java и .NET;
- SnapStart для Java кратно ускоряет старт за счёт снимка инициализированного окружения;
- при исчерпании лимита вызовы получают троттлинг (429), асинхронные события ставятся
  в очередь и ретраятся.

## Функция в VPC

Функции по умолчанию работают вне вашей VPC и имеют выход в интернет. Подключение к
VPC нужно для доступа к RDS, ElastiCache, внутренним сервисам. После подключения выход
в интернет пропадает: нужен NAT Gateway для публичных API или interface endpoints для
сервисов AWS. Это ровно та ловушка, где «функция не может обратиться к внешнему API»
решается NAT, а не правкой security group.

## Слои, образы, окружение

Layer — общий код и зависимости, до 5 слоёв на функцию; удобно для SDK, клиентских
библиотек и расширения Secrets Manager/Parameter Store. Образ контейнера до 10 ГБ
подходит для крупных зависимостей ML. Переменные окружения шифруются KMS; секреты
хранят в Secrets Manager и достают через расширение с кэшем, а не хардкодят.

Версии и алиасы дают контролируемый выкат: alias `prod` с весами направляет процент
трафика на новую версию (canary), откат мгновенный.

## Стоимость

Плата = число запросов + GB-секунды. Увеличение памяти повышает и цену за миллисекунду,
и скорость: часто функция с 1024 МБ дешевле, чем со 128 МБ, потому что заканчивает
в разы быстрее. AWS Lambda Power Tuning подбирает оптимум. Compute Savings Plans
покрывают Lambda наравне с EC2 и Fargate.

## API Gateway

| Тип API | Протокол | Особенности |
|---|---|---|
| REST | HTTP | максимум возможностей: кэш, usage plans, API keys, WAF, request validation |
| HTTP | HTTP | дешевле и быстрее, JWT-авторизация, меньше функций |
| WebSocket | WSS | двусторонняя связь, чаты, уведомления |

Возможности, которые спрашивают: throttling и usage plans для партнёров, кэш ответов
для снижения нагрузки, авторизация через IAM, Cognito или Lambda authorizer, интеграция
напрямую с сервисами (например, положить сообщение в SQS без функции), приватные API
через interface endpoint, стадии (dev, prod) и canary-выкаты.

Lambda function URL — прямой HTTPS-эндпоинт функции с авторизацией IAM или без неё.
Это правильный ответ там, где нужен один вызов одной функции и не нужны маршрутизация,
throttling, ключи и трансформации: API Gateway в такой задаче лишний сервис.

## Step Functions

Оркестратор состояний: последовательность, параллель, условия, ретраи, таймауты,
компенсации. Standard workflow — до года, оплата за переход, exactly-once; Express —
до 5 минут, оплата за время, для высокочастотных событий. Ответ на «сложный процесс
из нескольких шагов с ретраями и ветвлением» и на «обработка дольше 15 минут, но
логика разбивается на шаги».

## Что спрашивают на экзамене

1. «Обработать изображение при загрузке в S3» — событие S3 плюс Lambda.
2. «Пик запросов ломает базу» — reserved concurrency и RDS Proxy.
3. «Первый запрос после простоя слишком медленный» — provisioned concurrency
   или SnapStart.
4. «Функция не видит базу в VPC» — подключить к VPC и открыть security group.
5. «Функция в VPC перестала ходить в интернет» — NAT Gateway или endpoint.
6. «Нужен один HTTPS-эндпоинт для одной функции, минимум сервисов» — function URL.
7. «Задача идёт 40 минут» — Fargate, Batch или Step Functions, не Lambda.
8. «Сообщения должны обрабатываться строго по порядку» — SQS FIFO и обработчик
   с конкурентностью, ограниченной группой сообщений.

## Числа, которые надо помнить

- 15 минут максимум, 10 240 МБ памяти, до 6 vCPU при максимальной памяти;
- пакет 50 МБ zip и 250 МБ распакованный, образ до 10 ГБ;
- payload 6 МБ синхронно и 256 КБ асинхронно;
- `/tmp` от 512 МБ до 10 ГБ;
- 1000 одновременных выполнений по умолчанию на аккаунт и регион;
- асинхронные вызовы ретраятся дважды, события хранятся до 6 часов;
- batch size до 10 000 записей для Kinesis и DynamoDB Streams, до 10 000 для SQS
  в режиме стандартной очереди;
- API Gateway: таймаут интеграции 29 секунд, payload 10 МБ.

## Как читать формулировку

| В тексте вопроса | Ответ |
|---|---|
| «no servers to manage, pay per request» | Lambda |
| «processing takes 30 minutes» | Fargate, Batch или Step Functions |
| «cold start unacceptable» | provisioned concurrency, SnapStart |
| «protect the database from too many connections» | reserved concurrency плюс RDS Proxy |
| «function cannot reach the internet» | NAT Gateway или endpoint |
| «single function needs an HTTPS endpoint» | function URL |
| «throttle partner APIs, issue API keys» | API Gateway usage plans |
| «coordinate multiple steps with retries» | Step Functions |

## Наблюдаемость и отладка

Логи функции идут в CloudWatch Logs, метрики Invocations, Errors, Throttles, Duration
и ConcurrentExecutions — в CloudWatch. X-Ray показывает трассы вызовов между сервисами
и помогает найти, где теряется время. Типовые алармы: рост Throttles (упёрлись в
конкурентность), рост Errors с DLQ (проблемные события), Duration у предела таймаута.
Для событий, которые нельзя терять, обязательны DLQ или Destinations: без них
асинхронное событие после двух ретраев исчезает.

## Мини-практикум

**1.** Функция обрабатывает файлы из бакета, при рекламной кампании часть событий
потерялась.
→ Очередь SQS перед функцией: буфер держит всплеск, ничего не теряется.

**2.** Java-функции долго стартуют, жёстких требований к задержке нет, бюджет важен.
→ SnapStart: снимок инициализированного окружения без оплаты постоянного резерва.

**3.** Сотрудники приходят утром одновременно, и первые запросы идут медленно.
→ Provisioned concurrency по расписанию перед началом рабочего дня.

**4.** Задача считает час и написана на нестандартном языке.
→ Это не Lambda: предел выполнения 15 минут, задачу отдают AWS Batch или контейнерам.
