# VPC

VPC — изолированная сеть в регионе с собственным диапазоном адресов. Подсеть привязана
к одной AZ, поэтому «ресурс в двух AZ» всегда означает минимум две подсети. Разбирать
сетевой вопрос удобно по цепочке: адресация → маршрут → security group → NACL → куда
идёт трафик наружу.

## Адресация и подсети

- CIDR от /16 до /28, менять после создания нельзя, но можно добавить вторичный CIDR;
- в каждой подсети AWS резервирует 5 адресов: сеть, VPC-роутер, DNS, будущее
  использование и broadcast; в подсети /24 доступно 251 адрес;
- публичная подсеть отличается от приватной единственным признаком: в её таблице
  маршрутов есть маршрут `0.0.0.0/0` на Internet Gateway;
- IPv6-адреса в AWS всегда публичные, «приватность» обеспечивает egress-only internet
  gateway, аналог NAT для IPv6.

## Выход в интернет

| Механизм | Направление | Примечание |
|---|---|---|
| Internet Gateway | вход и выход | нужен публичный IP или Elastic IP у ресурса |
| NAT Gateway | только исходящий | управляемый, масштабируется, платный за час и за ГБ |
| NAT Instance | только исходящий | ваш EC2, нужно отключать source/destination check |
| Egress-only IGW | только исходящий IPv6 | бесплатный |

NAT Gateway живёт в конкретной AZ. Отказоустойчивая схема — по одному NAT в каждой AZ
и маршруты приватных подсетей на «свой» NAT: так отказ зоны не рвёт связь остальным,
а межзонный трафик не оплачивается. Единственный NAT на весь VPC — и точка отказа,
и лишняя плата за cross-AZ трафик.

Стоимость NAT — постоянный источник вопросов на оптимизацию: трафик к S3 и DynamoDB
через NAT платный, через gateway endpoint бесплатный.

## Security groups и NACL

| | Security group | Network ACL |
|---|---|---|
| Уровень | ENI (инстанс) | подсеть |
| Состояние | stateful: ответ разрешён автоматически | stateless: нужны оба направления |
| Правила | только allow | allow и deny, обрабатываются по номеру |
| Область | несколько SG на ENI | один NACL на подсеть |
| Ссылки | можно указать другую SG как источник | только CIDR |

Практика экзамена: «заблокировать конкретный IP-адрес злоумышленника» — это NACL с
правилом deny, потому что security group не умеет запрещать. «Разрешить приложению
ходить в базу» — security group базы со ссылкой на security group приложения.

## Соединения между сетями

- VPC peering: один-к-одному, без транзита (A—B и B—C не дают A—C), CIDR не должны
  пересекаться, работает между регионами и аккаунтами;
- Transit Gateway: хаб для сотен VPC, VPN и Direct Connect, поддерживает таблицы
  маршрутизации для сегментации и межрегиональный peering — ответ для «много VPC,
  централизованная маршрутизация»;
- PrivateLink (interface endpoint): доступ к одному сервису по приватному IP без
  маршрутизации между сетями, CIDR могут пересекаться, трафик односторонний
  от потребителя к сервису;
- VPN и Direct Connect — см. главу про гибрид.

Выбор между peering и PrivateLink: нужен доступ ко всей сети — peering или TGW; нужен
доступ к одному приложению и не хочется соединять сети — PrivateLink.

## Endpoints

| Тип | Сервисы | Как работает | Цена |
|---|---|---|---|
| Gateway endpoint | S3, DynamoDB | запись в таблице маршрутов | бесплатно |
| Interface endpoint (PrivateLink) | большинство сервисов AWS и партнёрские | ENI с приватным IP + приватный DNS | почасово и за ГБ |
| Gateway Load Balancer endpoint | сторонние appliance | точка входа в GWLB | почасово и за ГБ |

Ключевая ловушка: gateway endpoint существует только для S3 и DynamoDB. Для SQS, KMS,
Secrets Manager, ECR, Systems Manager и остальных нужен interface endpoint. Требование
«трафик не должен выходить в интернет» + «сервис не S3 и не DynamoDB» = interface endpoint.

Доступ через endpoint ограничивается endpoint policy, а со стороны бакета — условием
`aws:SourceVpce` в bucket policy.

## DNS и разрешение имён

- атрибуты VPC `enableDnsSupport` и `enableDnsHostnames` включают AmazonProvidedDNS
  по адресу VPC+2;
- Route 53 Resolver endpoints: inbound — чтобы локальная сеть резолвила private hosted
  zone в AWS, outbound с правилами пересылки — чтобы AWS резолвил корпоративные зоны;
- private hosted zone связывается с одной или несколькими VPC;
- при interface endpoint включённый private DNS подменяет публичное имя сервиса на
  приватный адрес, и приложение не нужно менять.

## Наблюдаемость

VPC Flow Logs пишут метаданные соединений (кто, куда, порт, ACCEPT или REJECT) в
CloudWatch Logs, S3 или Kinesis Data Firehose. Содержимое пакетов они не показывают —
для этого нужен Traffic Mirroring. Ответ «понять, почему трафик не доходит» = Flow Logs;
«проанализировать полезную нагрузку и работу IDS» = Traffic Mirroring.
Reachability Analyzer и Network Access Analyzer проверяют достижимость и политику
доступа статически, без отправки трафика.

## Что спрашивают на экзамене

1. «Инстансы в приватной подсети должны скачивать обновления» — NAT Gateway в публичной
   подсети и маршрут из приватной.
2. «Уменьшить стоимость доступа к S3 из приватных подсетей» — gateway endpoint.
3. «Трафик к SQS/KMS не должен идти через интернет» — interface endpoint.
4. «Соединить 50 VPC и локальную сеть без сетки peering» — Transit Gateway.
5. «Предоставить своё SaaS-приложение клиентам в их VPC» — PrivateLink с endpoint service.
6. «Заблокировать конкретный адрес» — NACL deny.
7. «Понять, кто обращается к инстансу» — Flow Logs.
8. «Пересекающиеся CIDR у двух компаний после слияния» — PrivateLink или NAT, peering
   в этом случае невозможен.

## Проектирование адресного пространства

Практическое правило: выбирайте /16 на VPC и /24 на подсеть, оставляя запас на будущие
AZ и на подсети для endpoint-ENI, баз данных и Transit Gateway attachment. Диапазоны
не должны пересекаться ни с локальной сетью, ни с сетями партнёров — иначе peering и
VPN станут невозможны, а единственным выходом останутся PrivateLink или NAT с трансляцией.

Типовая раскладка на три AZ:

| Подсеть | Назначение | Маршрут по умолчанию |
|---|---|---|
| public-a/b/c | ALB, NAT Gateway, bastion | Internet Gateway |
| app-a/b/c | EC2, ECS, Lambda с VPC-доступом | NAT Gateway своей AZ |
| data-a/b/c | RDS, ElastiCache, Redshift | нет маршрута наружу |
| tgw-a/b/c | вложения Transit Gateway | Transit Gateway |

Подсеть для базы без маршрута в интернет — самый простой способ ответить на требование
«база не должна быть доступна из интернета»: даже ошибочная security group не сделает
её публичной.

## Сегментация и централизованный выход

В крупных ландшафтах трафик наружу собирают в отдельном egress-VPC: приватные VPC
отправляют `0.0.0.0/0` в Transit Gateway, а NAT Gateway и Network Firewall стоят
в одном месте. Это дешевле, чем NAT в каждом VPC, и даёт единую точку фильтрации.
Обратная сторона — межзонный и межсетевой трафик через TGW тарифицируется за ГБ,
поэтому для двух-трёх VPC такая схема обычно избыточна.

Shared VPC через AWS RAM позволяет одному аккаунту владеть сетью, а другим — запускать
ресурсы в её подсетях. Ответ на «централизованное управление сетью при десятках
аккаунтов приложений».
