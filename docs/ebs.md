# EBS

Сетевой блочный том, подключаемый к инстансу в той же зоне доступности. Том — это
диск: файловая система, база, журнал. Данные реплицируются внутри AZ, поэтому отказ
зоны означает недоступность тома; защита от этого — снапшоты и репликация на уровне
приложения.

## Типы томов

| Тип | Класс | IOPS | Пропускная способность | Назначение |
|---|---|---|---|---|
| gp3 | SSD | 3000 базово, до 16 000 | 125 МБ/с базово, до 1000 | универсальный выбор по умолчанию |
| gp2 | SSD | 3 IOPS на ГБ, до 16 000 | до 250 МБ/с | предыдущее поколение |
| io2 / io2 Block Express | SSD | до 256 000 | до 4000 МБ/с | критичные базы, максимум надёжности |
| io1 | SSD | до 64 000 | до 1000 МБ/с | предыдущее поколение provisioned IOPS |
| st1 | HDD | до 500 | до 500 МБ/с | последовательные большие объёмы, логи, big data |
| sc1 | HDD | до 250 | до 250 МБ/с | холодные данные, минимальная цена |

Практические выводы:

- gp3 позволяет менять IOPS и пропускную способность независимо от объёма, поэтому
  «нужно больше IOPS, но не нужно больше места» решается переходом с gp2 на gp3, а не
  раздуванием тома;
- HDD-типы нельзя использовать как загрузочные и они плохи для случайного доступа;
- io2 Block Express даёт наибольшие показатели и durability 99.999 процентов;
- Multi-Attach (io1/io2) подключает том к нескольким инстансам в одной AZ, но требует
  кластерной файловой системы — это не замена EFS.

## Изменение и обслуживание

Elastic Volumes меняют размер, тип и параметры производительности на лету, без
остановки инстанса; уменьшить объём нельзя. После расширения тома нужно расширить
файловую систему внутри ОС — шаг, который любят упоминать в вариантах ответа.

Инициализация тома из снапшота: блоки подтягиваются из S3 при первом обращении, что
даёт замедление; Fast Snapshot Restore убирает эту задержку за отдельную плату.

## Снапшоты

- инкрементальные, хранятся в S3 (в служебном хранилище AWS), считаются по фактически
  изменённым блокам;
- копируются между регионами и аккаунтами, могут перешифровываться при копировании;
- Data Lifecycle Manager или AWS Backup создают их по расписанию и удаляют по политике;
- Recycle Bin защищает от случайного удаления снапшотов;
- снапшоты можно архивировать в Archive tier для долгого хранения по низкой цене
  (восстановление занимает часы).

Снапшот — основной механизм миграции тома между AZ и регионами: создать снапшот,
создать том в нужной зоне или скопировать в нужный регион.

## Шифрование

Шифрование включается при создании тома и распространяется на снапшоты и созданные
из них тома. Незашифрованный том нельзя зашифровать на месте: делают снапшот, копируют
его с указанием ключа, создают из копии новый том. Настройка аккаунта «encryption by
default» гарантирует шифрование всех новых томов и снапшотов в регионе — это ответ на
требование «незашифрованные тома создавать нельзя».

## EBS против instance store

| | EBS | Instance store |
|---|---|---|
| Данные при stop/terminate | сохраняются (кроме root по умолчанию) | теряются |
| Отказ хоста | том цел | данные потеряны |
| Производительность | высокая, зависит от типа | максимальная, локальный NVMe |
| Снапшоты | да | нет |
| Цена | за ГБ и IOPS | входит в цену инстанса |

Instance store выбирают для кэша, временных данных, буферов и реплицируемых на уровне
приложения кластеров (Cassandra, Kafka), где потеря узла допустима.

## Мониторинг и диагностика

Метрики CloudWatch: VolumeReadOps, VolumeWriteOps, VolumeQueueLength, BurstBalance
для gp2 и HDD. Исчерпанный BurstBalance — прямая причина «диски внезапно тормозят
после нескольких часов работы», лечится переходом на gp3 или io2. Ограничение
пропускной способности может лежать и на стороне инстанса: у каждого типа есть предел
EBS-bandwidth, поэтому «увеличили IOPS тома, а быстрее не стало» решается сменой типа
инстанса на EBS-optimized с большим лимитом.

## Что спрашивают на экзамене

1. «Нужен максимальный и предсказуемый IOPS для базы» — io2 (Block Express).
2. «Дёшево хранить последовательные логи большого объёма» — st1.
3. «IOPS не хватает, но место есть» — gp3 с провиженингом IOPS.
4. «Перенести том в другую AZ» — снапшот и создание тома в нужной зоне.
5. «Требуется шифрование существующих томов» — снапшот, копия с ключом, новый том.
6. «Данные должны пережить terminate инстанса» — EBS с `DeleteOnTermination=false`.
7. «Общий доступ к файлам с нескольких инстансов в разных AZ» — не EBS, а EFS.
8. «Автоматические ежедневные бэкапы дисков с хранением 30 дней» — Data Lifecycle
   Manager или AWS Backup.

## Числа, которые надо помнить

- gp3: базово 3000 IOPS и 125 МБ/с независимо от объёма, максимум 16 000 IOPS
  и 1000 МБ/с;
- gp2: 3 IOPS на ГБ, burst до 3000 для томов меньше 1 ТБ;
- io2 Block Express: до 256 000 IOPS, 4000 МБ/с, соотношение до 1000 IOPS на ГБ;
- st1 и sc1 начинаются от 125 ГБ, оптимизированы под последовательный доступ;
- том живёт в одной AZ, перенос — только через снапшот;
- снапшоты инкрементальные, первый содержит все занятые блоки;
- Multi-Attach: до 16 инстансов в одной AZ, только io1 и io2.

## Как читать формулировку

| В тексте вопроса | Ответ |
|---|---|
| «highest and most consistent IOPS for a database» | io2 Block Express |
| «throughput for large sequential logs at low cost» | st1 |
| «need more IOPS but not more capacity» | gp3 |
| «move the volume to another AZ» | снапшот и создание тома в целевой зоне |
| «all new volumes must be encrypted» | encryption by default в настройках аккаунта |
| «data must survive instance termination» | отключить DeleteOnTermination |
| «shared access from many instances across AZs» | EFS, а не EBS |
| «temporary scratch space with maximum speed» | instance store |

## Чек-лист операций

Расширение тома: изменить размер, затем расширить раздел и файловую систему в ОС.
Смена типа: Elastic Volumes на лету, состояние optimizing может длиться часы, но том
доступен. Перенос между аккаунтами: поделиться снапшотом (для зашифрованного —
поделиться также ключом KMS), скопировать снапшот в свой аккаунт, создать том.
Регулярные бэкапы: политика Data Lifecycle Manager или план AWS Backup с копированием
в другой регион для DR.

## Мини-практикум

**1.** База на gp2 объёмом 200 ГБ упирается в 600 IOPS, места хватает.
→ Перейти на gp3 и задать нужные IOPS независимо от объёма.

**2.** Требуется зашифровать существующий незашифрованный том.
→ Снапшот, копия снапшота с указанием ключа KMS, создание нового тома и подмена.

**3.** Инстанс перезапустили, и временные данные исчезли.
→ Данные лежали на instance store; для сохранности нужен EBS-том.

**4.** Нужно гарантировать, что незашифрованные тома в регионе больше не создаются.
→ Включить encryption by default в настройках EC2 для аккаунта и региона.
