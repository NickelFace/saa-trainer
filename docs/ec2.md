# EC2

Виртуальная машина в чужом дата-центре: вы отвечаете за ОС, патчи, приложение и
конфигурацию, AWS — за гипервизор, железо и сеть. На экзамене EC2 почти всегда
конкурирует с управляемыми сервисами, и вопрос «нужно ли здесь вообще EC2» стоит
задавать первым.

## Семейства инстансов

| Семейство | Буквы | Профиль | Типовые задачи |
|---|---|---|---|
| General purpose | T, M | сбалансированный | веб-серверы, небольшие БД, приложения |
| Compute optimized | C | много CPU на память | пакетная обработка, HPC-узлы, кодирование видео |
| Memory optimized | R, X, z1d | много памяти | in-memory кэш, SAP HANA, большие СУБД |
| Storage optimized | I, D, H | локальный NVMe/HDD | NoSQL с высоким IOPS, data warehouse узлы |
| Accelerated | P, G, Inf, Trn | GPU и ускорители | обучение и инференс моделей, графика |

T-семейство работает на кредитах CPU: базовый уровень плюс накопленные кредиты. При
исчерпании кредитов в режиме standard инстанс троттлится, в режиме unlimited работает
на полной скорости за доплату. Постоянная высокая загрузка на T — типовая ошибка
дизайна, ответ — перейти на M или C.

Если в вопросе сказано «high memory utilization» и обсуждается выбор типа — ответ
memory optimized для всех компонентов, у которых высокая память, независимо от того,
приложение это или база.

## Модели покупки

| Модель | Скидка | Обязательство | Когда |
|---|---|---|---|
| On-Demand | нет | нет | непредсказуемая нагрузка, разработка, пики |
| Savings Plans | до 72% | сумма в час на 1 или 3 года | базовая нагрузка, гибкость по типам |
| Reserved Instances | до 72% | конкретная конфигурация на 1 или 3 года | стабильная нагрузка, нужна capacity reservation |
| Spot | до 90% | нет, прерывание за 2 минуты | отказоустойчивые пакетные задачи |
| Dedicated Host | — | физический сервер | лицензии с привязкой к сокетам, регуляторика |
| Dedicated Instance | — | изоляция на уровне железа | требования изоляции без привязки лицензий |

Разница, которую любят проверять:

- Compute Savings Plans действуют на EC2, Fargate и Lambda и не привязаны к региону,
  семейству и ОС; EC2 Instance Savings Plans дешевле, но фиксируют семейство и регион;
- Standard RI дают максимальную скидку, но не меняют семейство; Convertible RI можно
  обменять на другую конфигурацию;
- Capacity Reservation резервирует ёмкость в AZ и не даёт скидки сама по себе;
  скидку добавляют RI или Savings Plans;
- Spot нельзя использовать там, где прерывание недопустимо; Spot Fleet и ASG с
  mixed instances policy смешивают On-Demand и Spot в одной группе.

Типовой дизайн для стабильного сервиса с пиками: базовая часть на Savings Plans или RI,
пики на On-Demand, фоновые пакетные задачи на Spot.

## Хранилище инстанса

- EBS — сетевой том, переживает остановку инстанса, снапшоты в S3, шифрование KMS.
- Instance store — физический диск гипервизора, максимум IOPS, но данные исчезают при
  остановке или отказе хоста. Ответ там, где нужен временный кэш или scratch-раздел.
- Root volume по умолчанию удаляется при terminate, дополнительные тома — нет.

## Размещение и сеть

Placement groups:

- Cluster — инстансы в одной AZ и одной стойке, минимальная задержка и до 100 Гбит/с
  между узлами; ответ для HPC и тесно связанных вычислений;
- Spread — инстансы на разном железе, максимум 7 на AZ; ответ для нескольких критичных
  узлов, которые не должны падать вместе;
- Partition — независимые группы стоек, до 7 партиций на AZ; ответ для HDFS, Cassandra,
  Kafka, где кластер сам знает про топологию.

Сетевые опции: ENA и Enhanced Networking по умолчанию на современных типах, EFA для
HPC с MPI, несколько ENI для разделения трафика управления и данных.

## Метаданные, роли и загрузка

- Роль IAM выдаётся инстансу через instance profile; ключи внутри AMI или в файлах —
  всегда неправильный ответ.
- IMDSv2 (session-oriented) защищает от SSRF-кражи временных ключей, требуйте его
  в вопросах про компрометацию метаданных.
- User data выполняется один раз при первом запуске, cloud-init.
- Golden AMI сокращает время запуска и делает конфигурацию воспроизводимой; EC2 Image
  Builder автоматизирует сборку и патчинг образов.

## Жизненный цикл и обслуживание

- Stop/Start переносит инстанс на другой хост, публичный IPv4 меняется (если не Elastic IP);
- Hibernate сохраняет RAM в корневой том и восстанавливает состояние;
- Auto Recovery и события Scheduled Maintenance закрывают деградацию железа;
- Systems Manager Session Manager даёт доступ к консоли без SSH, открытых портов и
  bastion-хоста — правильный ответ почти во всех вопросах «как безопасно попасть на
  инстанс в приватной подсети».

## Что спрашивают на экзамене

1. «Уменьшить стоимость стабильной круглосуточной нагрузки без изменения архитектуры» —
   Savings Plans или RI, а не Spot и не ASG.
2. «Пакетная обработка, задача может быть перезапущена» — Spot, часто в связке с SQS.
3. «Лицензия по физическим сокетам, BYOL» — Dedicated Host, а не Dedicated Instance.
4. «Задержка между узлами кластера должна быть минимальной» — cluster placement group.
5. «Инстансы не должны падать одновременно из-за одного узла» — spread placement group.
6. «Доступ администратора без открытых портов и ключей» — SSM Session Manager.
7. «Приложение нельзя переписывать, но нужно снять администрирование ОС» — сначала
   Elastic Beanstalk или контейнеры, потом уже EC2 с автоматизацией.
8. «Нужен пик производительности диска только на время обработки» — instance store или
   io2 Block Express, а не gp2 с большим объёмом.

## Мониторинг и лимиты

CloudWatch по умолчанию собирает метрики гипервизора: CPU, диск и сеть на уровне
устройства, статусы проверок. Память и занятость файловой системы гипервизор не видит —
их даёт CloudWatch agent внутри ОС. Вопрос «нужно алертить по памяти на EC2» всегда
решается установкой агента, а не встроенными метриками.

Detailed monitoring переводит метрики с интервала 5 минут на 1 минуту и влияет на
скорость реакции автоскейлинга. Квоты на число vCPU в регионе считаются по семействам
(отдельно On-Demand Standard, отдельно Spot) и поднимаются через Service Quotas — это
частый ответ на «не удаётся запустить нужное количество инстансов».

## EC2 против управляемых сервисов

| Требование | EC2 подходит | Лучше выбрать |
|---|---|---|
| Нужен полный контроль над ОС и ядром | да | — |
| Нестандартное ПО с лицензией на сокеты | да, Dedicated Host | — |
| Веб-приложение на стандартном стеке | можно | Elastic Beanstalk, ECS Fargate |
| Событийная обработка секундами | нет | Lambda |
| Пакетные задачи с очередью | можно | AWS Batch, ECS на Spot |
| Реляционная база | почти никогда | RDS, Aurora |

Формулировки «minimize operational overhead», «least management effort», «no servers
to manage» почти всегда уводят ответ от EC2 к управляемому сервису. Обратная подсказка:
«legacy application that cannot be modified», «requires access to the operating system»,
«custom kernel modules» — остаёмся на EC2.

## Лицензии и соответствие

License Manager отслеживает использование лицензий с привязкой к ядрам, сокетам или
хостам и запрещает запуск сверх лимита. Для BYOL Windows и SQL Server с привязкой к
физическому железу нужен Dedicated Host, у которого видно сокеты и физические ядра.
Dedicated Instance изолирует железо, но не даёт видимости и привязки сокетов, поэтому
в лицензионных вопросах он неверный ответ.

## Числа, которые надо помнить

- тарификация посекундная с минимумом 60 секунд (Linux); Windows и часть образов из
  Marketplace — по часам;
- обязательства берутся на 1 или 3 года: Compute Savings Plan даёт до 66% экономии,
  EC2 Instance Savings Plan и стандартные зарезервированные инстансы — до 72%,
  конвертируемые — примерно до 54%;
- спотовые инстансы дешевле по требованию до 90%, предупреждение об отзыве приходит
  за 2 минуты;
- spread placement group: не больше 7 инстансов в одной зоне доступности;
  partition — до 7 разделов на зону; cluster — одна зона доступности;
- метаданные инстанса доступны по адресу 169.254.169.254, IMDSv2 требует сессионного
  токена, и именно его требуют вопросы про защиту от SSRF;
- user data по умолчанию выполняется только при первом запуске;
- у инстанса две проверки состояния: системная (инфраструктура AWS) и проверка самого
  инстанса (его операционная система);
- данные instance store теряются при остановке и завершении, тома EBS переживают stop;
- Dedicated Host показывает сокеты и ядра — только он подходит для лицензий,
  привязанных к физическому оборудованию.

## Мини-практикум

**1.** Приложение работает круглосуточно, но через полгода планируется переход на другое
семейство инстансов.
→ Compute Savings Plan: скидка сохраняется при смене семейства, размера и даже сервиса.

**2.** Пакетные задания идут ночью шесть часов, потеря инстанса означает лишь повторную
обработку.
→ Спотовые инстансы: профиль нагрузки ровно тот, ради которого они существуют.

**3.** Узлы расчётного кластера обмениваются данными между собой, важна задержка сети.
→ Cluster placement group в одной зоне доступности.

**4.** Лицензия на коммерческое ПО куплена по сокетам и ядрам, нагрузка постоянная.
→ Dedicated Host с резервированием: и лицензия переносится, и цена ниже, чем по требованию.
