# Файловые хранилища

Когда нескольким серверам нужен один и тот же изменяемый набор файлов с обычной
файловой семантикой, S3 не подходит: нужен сетевой файловый доступ. Выбор идёт по
протоколу и по тому, чей это стек — Linux, Windows или специализированный.

## EFS

Эластичная файловая система NFS v4.1 для Linux. Растёт и сжимается сама, монтируется
одновременно тысячами клиентов из нескольких AZ, оплачивается за использованное место.

- режимы доступности: Regional (несколько AZ, стандарт для отказоустойчивости) и
  One Zone (дешевле, но зависит от одной зоны);
- классы хранения: Standard и Infrequent Access, между ними двигает lifecycle-политика,
  Archive для редких данных;
- режимы производительности: General Purpose (низкая задержка, по умолчанию) и Max I/O
  (выше пропускная способность, выше задержка);
- режимы пропускной способности: Bursting, Provisioned и Elastic;
- доступ монтируется через mount target в каждой AZ; security group mount target
  должна принимать порт 2049 от клиентов;
- Access Points задают точку входа с фиксированным пользователем и каталогом — удобно
  для многоарендных приложений и для Lambda;
- шифрование в покое (KMS) и в передаче (TLS), политика файловой системы для контроля
  доступа, интеграция с IAM;
- реплика EFS в другой регион делается репликацией EFS или через AWS Backup.

Когда EFS правильный ответ: контент-каталог для нескольких веб-серверов, домашние
каталоги, общие данные для контейнеров ECS/EKS, обработка файлов, где приложение
умеет только файловый доступ.

## FSx: четыре разных сервиса

| Вариант | Протокол | Профиль | Типовой сценарий |
|---|---|---|---|
| FSx for Windows File Server | SMB | интеграция с Active Directory, ACL NTFS, DFS | файловые шары Windows, миграция с file-серверов |
| FSx for Lustre | Lustre (POSIX) | сотни ГБ/с, связка с S3 | HPC, ML-обучение, обработка больших датасетов |
| FSx for NetApp ONTAP | NFS, SMB, iSCSI | снапшоты, дедупликация, SnapMirror | миграция NetApp, мультипротокольный доступ |
| FSx for OpenZFS | NFS | ZFS-снапшоты, низкая задержка | миграция с ZFS-серверов, dev-окружения |

Ключевые подсказки в тексте вопроса: «Windows applications», «SMB», «Active Directory» —
FSx for Windows; «high-performance computing», «machine learning training», «process
data from S3 at high speed» — FSx for Lustre; «NetApp», «multi-protocol», «SnapMirror» —
ONTAP; «ZFS snapshots» — OpenZFS.

FSx for Lustre умеет связываться с бакетом S3: объекты видны как файлы, результаты
экспортируются обратно. Это стандартный ответ на «данные лежат в S3, но вычислительному
кластеру нужен POSIX-доступ с высокой скоростью».

## Сравнение с другими типами хранения

| Признак | S3 | EFS | FSx Windows | EBS |
|---|---|---|---|---|
| Доступ | HTTP API | NFS | SMB | блочное устройство |
| Одновременно с многих серверов | да | да | да | только io1/io2 Multi-Attach в одной AZ |
| Между AZ | да | да (Regional) | да (Multi-AZ) | нет |
| Частичная перезапись | нет | да | да | да |
| Цена | самая низкая | средняя | средняя и выше | зависит от типа тома |

## Резервное копирование

EFS и FSx интегрированы с AWS Backup: расписания, сроки хранения, копии в другой
регион и аккаунт, Vault Lock для неизменяемых копий. Для EFS исторически предлагали
решение «EFS-to-EFS backup» на CloudFormation — это устаревший шаблон, а не сервис,
и в современных ответах он неверен.

## Производительность и стоимость

- EFS оплачивается за хранение и, в Provisioned-режиме, за пропускную способность;
  перевод холодных файлов в IA снижает счёт в разы;
- One Zone-варианты дешевле примерно на половину, но не переживают отказ зоны;
- FSx оплачивается за провиженинговую ёмкость, пропускную способность и бэкапы;
- Lustre в режиме scratch дешевле и не реплицируется — подходит для временных вычислений,
  persistent — для долговременных данных.

## Что спрашивают на экзамене

1. «Несколько EC2 в разных AZ пишут в один каталог» — EFS.
2. «Приложение Windows требует SMB и доменных ACL» — FSx for Windows File Server.
3. «Обучение модели читает терабайты из S3 с максимальной скоростью» — FSx for Lustre
   с data repository association.
4. «Кластер приложений в одной AZ, нужен общий том с максимальным IOPS» — io2 Multi-Attach
   или instance store при допустимости потери.
5. «Мигрировать локальный NetApp с сохранением снапшотов» — FSx for NetApp ONTAP.
6. «Снизить стоимость общего хранилища, где 80 процентов файлов не трогали месяцами» —
   EFS lifecycle в Infrequent Access.
7. «Реплика файловой системы в другом регионе» — репликация EFS или AWS Backup.
8. «Файлы нужны только как объекты через API» — это S3, файловый сервис не нужен.

## Числа, которые надо помнить

- EFS: NFS v4.1, порт 2049, до тысяч клиентов, размер файловой системы не задаётся;
- EFS IA дешевле Standard примерно в 10 раз при плате за доступ к файлу;
- EFS One Zone дешевле Regional примерно вдвое, но живёт в одной AZ;
- FSx for Windows: SMB, интеграция с AD, Multi-AZ как отдельная опция при создании;
- FSx for Lustre: пропускная способность сотни ГБ/с, scratch (без репликации) и
  persistent (с репликацией) файловые системы;
- FSx for Lustre связывается с бакетом S3 и импортирует метаданные объектов как файлы.

## Как читать формулировку

| В тексте вопроса | Ответ |
|---|---|
| «shared file system for Linux instances across AZs» | EFS |
| «SMB shares, Active Directory, NTFS ACLs» | FSx for Windows |
| «HPC, machine learning training, sub-millisecond, from S3» | FSx for Lustre |
| «NetApp, SnapMirror, multi-protocol» | FSx for NetApp ONTAP |
| «ZFS snapshots» | FSx for OpenZFS |
| «lower cost for files not accessed in months» | EFS lifecycle в IA |
| «object storage over HTTP» | S3, файловый сервис не нужен |
| «single instance needs a fast local disk» | EBS io2 или instance store |

## Подключение и права

EFS монтируется через DNS-имя файловой системы, для Lambda и контейнеров используется
Access Point с фиксированным UID и корневым каталогом. Доступ ограничивается двумя
слоями: security group на mount target (порт 2049 от групп клиентов) и политика
файловой системы с действиями `elasticfilesystem:ClientMount` и `ClientWrite`. Для
FSx for Windows права определяются доменными ACL, а сервис-аккаунт AD должен иметь
права на присоединение к домену — деталь, которая появляется в вопросах о миграции
файловых серверов.

## Мини-практикум

**1.** Десяток веб-серверов в трёх AZ должны отдавать одинаковый каталог загруженных
пользователями файлов.
→ EFS Regional: монтируется во всех зонах, растёт автоматически.

**2.** Приложение на Windows требует SMB-шару с правами доменных групп.
→ FSx for Windows File Server с интеграцией в Active Directory.

**3.** Кластер обучения модели читает 20 ТБ из S3 и упирается в скорость.
→ FSx for Lustre со связкой с бакетом: объекты видны как файлы, скорость сотни ГБ/с.

**4.** 80 процентов файлов в EFS не открывались полгода, счёт растёт.
→ Lifecycle-политика EFS в Infrequent Access, при необходимости Archive.

## Связь с другими главами

- Объектное хранилище и выбор между файлом и объектом — глава про S3.
- Блочные тома, когда доступ нужен одному инстансу — глава про EBS.
- Перенос файловых шар в облако и гибридный доступ — глава про перенос данных.
- Монтирование общих томов в задачи и поды — глава про контейнеры.
- Централизованные бэкапы EFS и FSx — глава про управление.
