# Стоимость

Домен «Design Cost-Optimized Architectures» занимает пятую часть экзамена, но
стоимостные соображения появляются почти в каждом вопросе: формулировки
«MOST cost-effective», «minimize cost», «as low as possible» задают выбор между
технически равноценными вариантами.

## Из чего складывается счёт

| Категория | Что тарифицируется | Как экономят |
|---|---|---|
| Вычисления | часы или секунды инстансов, GB-секунды Lambda, ACU Aurora | Savings Plans, RI, Spot, right sizing, выключение простаивающих |
| Хранение | ГБ в месяц по классам, снапшоты, бэкапы | классы хранения, lifecycle, удаление старых снапшотов |
| Трафик | исходящий в интернет, между AZ, между регионами, через NAT | CloudFront, endpoints, локальность трафика |
| Запросы и операции | API-вызовы, RCU/WCU, LCU балансировщика, KMS-запросы | батчинг, кэш, Bucket Keys |
| Управляемые сервисы | почасовые ставки NAT, TGW attachment, interface endpoints | консолидация, отказ от лишних компонентов |

Входящий трафик в AWS бесплатен; исходящий стоит денег. Трафик между AZ оплачивается
в обе стороны, внутри одной AZ по приватным адресам — бесплатен. Это объясняет добрую
половину «дешёвых» ответов: убрать межзонные переходы, отдать контент через CloudFront,
заменить NAT на gateway endpoint.

## Модели оплаты вычислений

Сводка выбора:

- постоянная нагрузка 24/7 → Savings Plans (Compute для гибкости, EC2 Instance для
  максимальной скидки) или Reserved Instances;
- прерываемые пакетные задачи → Spot, до 90 процентов дешевле;
- редкие короткие задачи → Lambda или Fargate, платите только за исполнение;
- окружения разработки → расписание запуска и остановки (Instance Scheduler),
  Aurora Serverless v2, остановка RDS;
- пики поверх базовой линии → On-Demand или Spot поверх зарезервированной базы.

## Инструменты

- Cost Explorer — анализ и прогноз расходов, разрезы по сервисам, тегам, аккаунтам,
  рекомендации по RI и Savings Plans;
- AWS Budgets — бюджеты по стоимости, использованию, покрытию RI с уведомлениями и
  автоматическими действиями (например, применить ограничивающую политику);
- Cost and Usage Report — детализация в S3 для анализа в Athena и QuickSight;
- Compute Optimizer — рекомендации по типам инстансов, томам EBS, функциям Lambda
  и ASG на основе фактических метрик;
- Trusted Advisor — проверки по пяти категориям, включая простаивающие ресурсы и
  неиспользуемые RI (полный набор проверок при Business и Enterprise поддержке);
- S3 Storage Lens и Storage Class Analysis — что перевести в холодные классы;
- Billing Conductor и cost allocation tags — распределение расходов по командам.

Разделение ролей: Budgets предупреждает и действует по порогу, Cost Explorer объясняет
прошлое и прогнозирует, Compute Optimizer говорит, что уменьшить, Trusted Advisor
находит явно лишнее.

## Типовые находки в архитектуре

| Симптом | Дешёвое решение |
|---|---|
| Трафик из приватных подсетей в S3 идёт через NAT | gateway endpoint |
| Один NAT Gateway обслуживает три AZ | NAT в каждой AZ (меньше межзонного трафика) |
| Раздача статики с EC2 | S3 плюс CloudFront |
| Логи и архивы лежат в S3 Standard годами | lifecycle в Glacier или Deep Archive |
| Снапшоты копятся без политики | Data Lifecycle Manager, AWS Backup |
| Dev-инстансы работают ночью и в выходные | расписание остановки |
| Оверсайз инстансов | Compute Optimizer, переход на gp3, T-семейство |
| Много мелких объектов в Standard-IA | вернуть в Standard или агрегировать |
| Отдельные аккаунты покупают RI | консолидированный биллинг в Organizations |
| Кластер БД простаивает по ночам | Aurora Serverless v2 или остановка |

## Стоимость надёжности

Экзамен часто противопоставляет цену и отказоустойчивость. Ориентиры: One Zone-классы
и одна AZ дешевле, но не переживают отказ зоны; pilot light дешевле warm standby, но
восстанавливается дольше; репликация в другой регион всегда добавляет и хранение,
и трафик. Если в вопросе есть и «cost-effective», и «highly available», выбирают
самый дешёвый вариант из тех, что действительно закрывают требование доступности,
а не самый дешёвый вообще.

## Что спрашивают на экзамене

1. «Снизить стоимость стабильной круглосуточной нагрузки» — Savings Plans или RI.
2. «Обработка может прерываться» — Spot.
3. «Данные читаются раз в год, извлечение за часы приемлемо» — Glacier Deep Archive.
4. «Счёт за NAT слишком велик» — endpoints для S3 и DynamoDB.
5. «Нужно предупреждение при превышении бюджета» — AWS Budgets с SNS.
6. «Понять, какие инстансы избыточны» — Compute Optimizer.
7. «Разнести затраты по командам» — cost allocation tags и Cost Explorer.
8. «Много аккаунтов, хотим общие скидки» — Organizations с консолидированным биллингом.

## Как читать формулировку

| В тексте вопроса | Ответ |
|---|---|
| «steady 24/7 workload, lowest cost» | Savings Plans или RI |
| «fault-tolerant batch jobs» | Spot |
| «accessed once a year, retrieval in hours is fine» | Glacier Deep Archive |
| «NAT gateway data processing charges» | gateway endpoints для S3 и DynamoDB |
| «alert when spending exceeds a threshold» | AWS Budgets |
| «which instances are oversized» | Compute Optimizer |
| «allocate costs to teams» | cost allocation tags и Cost Explorer |
| «multiple accounts, volume discounts» | Organizations с консолидированным биллингом |

## Порядок оптимизации архитектуры

1. Убрать простаивающее: незакреплённые Elastic IP, старые снапшоты, неиспользуемые
   тома, тестовые окружения ночью.
2. Подобрать размер: Compute Optimizer, gp3 вместо gp2, актуальные поколения инстансов.
3. Закрыть базовую нагрузку обязательствами: Savings Plans, RI, а пики оставить
   On-Demand и Spot.
4. Перенести данные в правильный класс хранения и включить lifecycle.
5. Убрать лишний трафик: CloudFront для отдачи, endpoints вместо NAT, локальность AZ.
6. Заменить самоуправляемые компоненты управляемыми там, где это дешевле по совокупной
   стоимости владения (RDS вместо базы на EC2, Fargate вместо кластера узлов).
7. Ввести контроль: бюджеты, теги, регулярный разбор Cost Explorer и Trusted Advisor.

## Мини-практикум

**1.** Счёт за NAT Gateway превышает стоимость самих инстансов, основной трафик — в S3.
→ Gateway endpoint для S3: трафик перестаёт идти через NAT и не тарифицируется.

**2.** Тестовые окружения работают круглосуточно, используются с 9 до 18 по будням.
→ Расписание запуска и остановки (Instance Scheduler или EventBridge с SSM Automation).

**3.** Пять аккаунтов покупают резервы по отдельности и не выбирают их полностью.
→ Организация с консолидированным биллингом: скидки и покрытие RI распределяются
между аккаунтами.

**4.** Архив логов за пять лет лежит в S3 Standard, читается раз в год по требованию
аудита.
→ Lifecycle в Glacier Deep Archive, если приемлемо извлечение за часы.

## Связь с другими главами

- Модели покупки вычислений — глава про EC2.
- Классы хранения и lifecycle — глава про S3.
- Трафик, NAT и endpoints — глава про VPC.
- Кэш и снижение исходящего трафика — глава про CloudFront.
- Serverless-варианты баз данных — главы про Aurora и DynamoDB.

## Ловушки формулировок

Слово «cost-effective» в вопросе не означает «самый дешёвый вариант из списка»: оно
означает «самый дешёвый из тех, что выполняют все остальные требования». Если рядом
стоят «highly available» или «no data loss», варианты с одной AZ и без репликации
отпадают, даже если они дешевле.

Обратная ловушка — «operational overhead». Управляемый сервис часто дороже по счёту,
но выигрывает, когда требование сформулировано про трудозатраты, а не про деньги.
Читайте, что именно требуется минимизировать: стоимость, время восстановления или
объём администрирования.

## Числа, которые надо помнить

- обязательства берутся на 1 или 3 года: Compute Savings Plan до 66% экономии,
  EC2 Instance Savings Plan и стандартные зарезервированные инстансы до 72%,
  конвертируемые — около 54%, спотовые инстансы до 90%;
- полная предоплата дешевле частичной, частичная — дешевле варианта без предоплаты;
- данные о затратах обновляются не чаще раза в сутки, поэтому мгновенного контроля
  расходов ни один инструмент не даёт;
- Cost Explorer показывает историю за 12 месяцев и строит прогноз на 12 месяцев вперёд;
  почасовая детализация и данные по ресурсам включаются отдельно и стоят денег;
- первые два бюджета в AWS Budgets бесплатны, дальше берётся плата за каждый бюджет в день;
- теги распределения затрат нужно активировать вручную, и задним числом они не работают:
  в отчётах они появляются только с момента активации;
- межзональный трафик внутри региона платный, внутри одной зоны доступности по
  приватным адресам — бесплатный;
- NAT-шлюз оплачивается и по часам, и за каждый гигабайт, поэтому в вопросах про
  экономию его часто заменяют на gateway endpoint.
