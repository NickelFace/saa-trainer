# RDS

Управляемая реляционная СУБД: AWS берёт на себя установку, патчи, бэкапы, отказоустойчивое
переключение и мониторинг, вы отвечаете за схему, запросы и параметры. Движки: MySQL,
PostgreSQL, MariaDB, Oracle, SQL Server, Db2 и семейство Aurora (отдельная глава).

## Multi-AZ: два разных механизма

| | Multi-AZ instance | Multi-AZ DB cluster |
|---|---|---|
| Состав | primary + standby | writer + 2 readable standby |
| Standby читаемый | нет | да, есть reader endpoint |
| Зон | 2 | 3 |
| Переключение | 60–120 секунд | обычно менее 35 секунд |
| Движки | все | MySQL и PostgreSQL |
| Назначение | доступность | доступность плюс чтение |

Ключевая ловушка: в классическом Multi-AZ standby не обслуживает чтение. Если в
требовании есть и высокая доступность, и разгрузка чтения, ответ — либо Multi-AZ DB
cluster, либо Multi-AZ instance плюс read replica, а не «читать со standby».

Failover происходит автоматически при отказе зоны, инстанса, сети или во время
обслуживания; приложение переподключается по тому же DNS-имени, менять строку
подключения не нужно.

## Read replicas

- асинхронная репликация, до 15 реплик, возможны в другой AZ, регионе и аккаунте;
- каждая реплика имеет собственный endpoint — приложение должно направлять на неё
  запросы чтения само;
- реплику можно повысить до самостоятельной базы (promote) — это способ миграции
  и разделения нагрузки, но не автоматический failover;
- отставание отслеживается метрикой ReplicaLag; при требовании строгой согласованности
  чтения с реплики недопустимы;
- реплика в другом регионе снижает задержку для удалённых читателей и служит частью
  плана DR.

## Резервное копирование и восстановление

- Автоматические бэкапы: срок хранения от 1 до 35 дней, включают журналы транзакций
  и дают point-in-time recovery с точностью около 5 минут;
- ручные снапшоты хранятся, пока их не удалят, и переживают удаление базы;
- восстановление всегда создаёт новый инстанс с новым endpoint;
- копирование снапшота в другой регион — базовый механизм DR; при шифровании нужен
  ключ целевого региона;
- AWS Backup централизует политики хранения для RDS вместе с другими сервисами.

RPO определяется журналами (минуты), RTO — временем восстановления снапшота (десятки
минут и больше). Если требуют RPO и RTO в секундах, RDS-снапшоты не подходят — нужны
Aurora Global Database или репликация.

## Производительность и масштабирование

- вертикально — изменение класса инстанса (с даунтаймом или через failover Multi-AZ);
- горизонтально по чтению — read replicas или кэш ElastiCache;
- по записи — шардирование на стороне приложения, смена движка или переход в Aurora;
- Storage autoscaling увеличивает том автоматически, уменьшить его нельзя;
- типы хранилища: gp3 для большинства задач, io1/io2 для гарантированного IOPS,
  magnetic — устаревший;
- Performance Insights показывает нагрузку по запросам и ожиданиям, Enhanced Monitoring —
  метрики ОС с интервалом до 1 секунды.

RDS Proxy решает проблему тысяч коротких подключений (типично для Lambda): пул
соединений, ускоренный failover, интеграция с Secrets Manager и IAM-аутентификацией.
Он не ускоряет сами запросы и не заменяет read replica — это про соединения, а не
про производительность чтения.

## Безопасность

- база в приватной подсети, security group разрешает доступ только от группы приложения;
- шифрование в покое включается при создании, TLS в передаче — параметром движка;
- аутентификация по IAM убирает пароли для приложений; пароли администраторов —
  в Secrets Manager с ротацией;
- аудит: логи движка выгружаются в CloudWatch Logs, события API — в CloudTrail;
- Multi-AZ и снапшоты не отменяют требования шифрования: снапшот незашифрованной базы
  тоже незашифрован.

## Миграция

DMS переносит данные из локальной или облачной СУБД с минимальным простоем, поддерживает
полную загрузку и CDC. Schema Conversion Tool конвертирует схему и код при смене движка
(Oracle в PostgreSQL, SQL Server в MySQL). Типовая пара «DMS + SCT» — стандартный ответ
на гетерогенную миграцию, «просто DMS» — на однородную.

## Что спрашивают на экзамене

1. «Отчёты грузят базу, нужны свежие данные с небольшим отставанием» — read replica.
2. «Пережить отказ AZ без потери данных» — Multi-AZ (синхронная репликация).
3. «Lambda исчерпывает соединения к базе» — RDS Proxy.
4. «Восстановить состояние на 10 минут назад» — point-in-time recovery.
5. «Ежемесячный отчёт грузит базу раз в месяц, остальное время простой» — либо реплика
   по требованию, либо выгрузка в S3 и Athena.
6. «Мигрировать Oracle в PostgreSQL с минимальным простоем» — SCT для схемы, DMS с CDC
   для данных.
7. «База должна выдержать отказ региона с RPO минуты» — кросс-региональная реплика или
   Aurora Global Database.
8. «Не хотим управлять патчами и бэкапами» — RDS вместо базы на EC2.

## Обслуживание и окна

Патчи движка и изменения класса применяются в maintenance window; при Multi-AZ AWS
обновляет standby, затем делает failover, поэтому простой ограничен временем
переключения. Blue/Green Deployments создают полную копию окружения, применяют
изменения на зелёной стороне и переключают трафик за секунды — правильный ответ на
«обновить мажорную версию с минимальным простоем».

Reserved Instances для RDS работают так же, как для EC2, и покрывают стабильную нагрузку;
у dev-баз дешевле остановка на ночь (RDS можно остановить максимум на 7 суток, дальше
инстанс запускается автоматически) или переход на Aurora Serverless v2.

## Выбор между RDS, Aurora и базой на EC2

| Требование | Ответ |
|---|---|
| Стандартный движок, минимум администрирования | RDS |
| Максимальная пропускная способность и быстрый failover | Aurora |
| Нужен доступ к файловой системе, нестандартные расширения, свой патч | база на EC2 |
| Глобальные читатели с задержкой репликации около секунды | Aurora Global Database |
| Непредсказуемая нагрузка с простоями | Aurora Serverless v2 |
| Лицензия Oracle или SQL Server с привязкой к сокетам | RDS с BYOL или EC2 на Dedicated Host |

Любая формулировка «reduce operational overhead» в связке с реляционной базой на EC2 —
это приглашение мигрировать в RDS или Aurora, а не улучшать скрипты обслуживания.

## Как читать формулировку

| В тексте вопроса | Ответ |
|---|---|
| «offload reporting queries» | read replica |
| «survive an AZ failure with no data loss» | Multi-AZ (синхронная репликация) |
| «Lambda exhausts database connections» | RDS Proxy |
| «restore to any point in the last week» | PITR из автоматических бэкапов |
| «minimal downtime major version upgrade» | Blue/Green Deployments |
| «migrate Oracle to PostgreSQL» | SCT плюс DMS с CDC |
| «encrypt an existing database» | снапшот, копия с ключом, восстановление |
| «cross-Region disaster recovery, RPO minutes» | кросс-региональная реплика или Aurora Global Database |
