# S3

Object storage: a flat key space inside a bucket, accessed over an HTTP API. It is not
a file system and not a block device — no partial object overwrites, no POSIX semantics,
no directories (the prefix `logs/2026/` is part of the key, not a folder).

Baseline facts the exam treats as given:

- a bucket name is globally unique, and a bucket lives in a single Region;
- an object can be up to 5 TB, a single-operation upload up to 5 GB, beyond that it's
  multipart;
- writes to any object are strongly consistent for reads immediately after the write is
  acknowledged (read-after-write) — there is no separate "eventual consistency" anymore;
- durability of eleven nines comes from replication within the Region; availability
  depends on the storage class.

## Storage classes

| Class | AZs | Min. duration | Min. size | Access | When it's chosen |
|---|:--:|:--:|:--:|---|---|
| Standard | 3+ | none | none | instant | active data, unpredictable access |
| Intelligent-Tiering | 3+ | none | none | instant | access pattern unknown or changing |
| Standard-IA | 3+ | 30 days | 128 KB | instant | infrequent access, but fault tolerance needed |
| One Zone-IA | 1 | 30 days | 128 KB | instant | reproducible copies, losing the AZ is acceptable |
| Glacier Instant Retrieval | 3+ | 90 days | 128 KB | milliseconds | archive with rare but instant reads |
| Glacier Flexible Retrieval | 3+ | 90 days | 40 KB | minutes to 12 hours | archive, accessed a few times a year |
| Glacier Deep Archive | 3+ | 180 days | 40 KB | 12–48 hours | long-term retention for regulatory reasons |
| Express One Zone | 1 | none | none | single-digit ms | hot data with a high request rate |

Key pricing mechanics: IA and Glacier classes charge less for storage but more for read
requests, plus there's a penalty for early deletion (you're billed the full minimum
duration) and for objects below the minimum billable size. That's why millions of small
files in Standard-IA end up costing more than in Standard — a classic trap in
cost-optimization questions.

Retrieval tiers from Glacier Flexible Retrieval: Expedited (1–5 minutes), Standard
(3–5 hours), Bulk (5–12 hours, the cheapest). For Deep Archive: Standard (12 hours) and
Bulk (up to 48 hours). If the question asks for retrieval "within a few minutes," Deep
Archive is disqualified by definition.

## Lifecycle

Lifecycle rules move objects between classes and delete them based on age. Scope is set
by prefix, tags, or object size.

```
Standard --(30 days)--> Standard-IA --(90 days)--> Glacier Flexible --(365)--> Deep Archive --> expire
```

Key things to remember:

- transitions to cheaper classes are allowed; moving back up is only done by copying
  (`RestoreObject` returns a temporary copy, it doesn't change the storage class);
- transition to IA is possible no earlier than 30 days after object creation;
- in a versioned bucket, rules apply separately to current and noncurrent versions, and
  also to incomplete multipart uploads (`AbortIncompleteMultipartUpload`);
- Intelligent-Tiering moves objects between tiers automatically and charges a
  per-object monitoring fee, so it's not cost-effective for very small objects.

If a requirement reads like "data is needed for the first 30 days, then almost never,
delete after 7 years, minimal manual work" — that's exactly a lifecycle rule, not a
Lambda script.

## Versioning, Object Lock, MFA Delete

Versioning is enabled on a bucket and can never be turned off again — only suspended
(Suspended). Deleting an object in a versioned bucket creates a delete marker; the
object itself remains and keeps being billed. Hence the standard requirement
"protect against accidental deletion and overwrite" = versioning.

Object Lock is WORM storage, enabled only on a bucket with versioning turned on (on an
existing bucket it requires a support request; on a new bucket it's set at creation
time). Two modes:

- Governance: a user with the `s3:BypassGovernanceRetention` permission can remove or
  shorten the retention period;
- Compliance: nobody can, including the root user, until the retention period expires.

Legal Hold is an indefinite deletion block on a version, removed by a separate
permission, and unrelated to the retention period.

MFA Delete protects against deleting versions and disabling versioning; it can only be
enabled by the root user, and only via CLI/API.

## Replication

CRR (to another Region) and SRR (within the same Region) both require versioning on
the source and destination, plus an IAM role for S3. Only new operations after the
rule is enabled get replicated; existing objects are migrated with S3 Batch
Replication.

- a delete marker is replicated only if that's explicitly enabled; deleting a specific
  version is never replicated;
- by default the replication chain doesn't continue (a replica isn't replicated
  further) — Replica Modification Sync exists for that;
- S3 Replication Time Control (RTC) provides a 15-minute SLA and metrics — the answer
  whenever a question needs predictable replication time;
- object ownership in the destination account is changed with the Owner Override
  option.

Why it's tested: CRR addresses requirements to keep a copy in another Region, to
reduce latency for readers in a different Region, and to isolate environments.

## Encryption

| Option | Who holds the key | Who encrypts | Notes |
|---|---|---|---|
| SSE-S3 (AES-256) | AWS | S3 | on by default for all new objects |
| SSE-KMS | KMS | S3 | audited in CloudTrail, controlled by key policy, subject to KMS limits |
| DSSE-KMS | KMS | S3 | double encryption for specific regulatory requirements |
| SSE-C | client | S3 | key is passed with every request, HTTPS only |
| client-side | client | client | S3 only ever sees already-encrypted bytes |

S3 Bucket Keys cut KMS request volume by up to 99 percent — the right answer when the
complaint is KMS cost or throttling during bulk uploads.

The requirement "encrypt everything put into the bucket" is met with a bucket policy
that `Deny`s requests missing the `x-amz-server-side-encryption` header, while
"traffic must be TLS only" is met with a policy condition on `aws:SecureTransport:
false`.

## Access

- Block Public Access — four account- and bucket-level flags that override any
  permissive policies. The first answer for "the bucket accidentally became public."
- Bucket policy — resource-based, works for cross-account access and for conditions
  (`aws:SourceIp`, `aws:SourceVpce`, `aws:PrincipalOrgID`).
- ACL — a legacy mechanism, disabled by default (Object Ownership = Bucket owner
  enforced). In modern answers, ACL is almost always the wrong option.
- Presigned URL — temporary access to a specific object on behalf of whoever signed
  it, without issuing credentials.
- Access Points — separate entry points with their own policies and names, useful
  when dozens of applications share one bucket and the bucket policy is getting
  unwieldy. Multi-Region Access Point adds a single global endpoint on top of buckets
  in different Regions.
- Object Lambda Access Point — transforms an object on the fly (masking PII,
  redaction) without creating a second copy of the data.
- VPC gateway endpoint for S3 — private access from a VPC without internet access and
  without NAT data-transfer charges.

## Performance and uploads

- 5,500 GETs and 3,500 PUTs per second per prefix; scaling is achieved with different
  prefixes — random hash prefixes on keys are no longer needed;
- multipart upload: mandatory from 5 GB, recommended from 100 MB, parts upload in
  parallel and are retried individually;
- S3 Transfer Acceleration routes traffic through the nearest CloudFront edge location
  to the bucket — the answer for "fast uploads of large files from multiple countries
  into one bucket";
- byte-range fetch speeds up reading large objects in parts;
- S3 Select reads a subset of CSV/JSON/Parquet data directly within S3;
- Storage Lens and Storage Class Analysis show what to move and where.

## What the exam asks

1. "Minimum storage cost with quarterly access, retrieval within minutes" — Glacier
   Flexible Retrieval, not Deep Archive (that's hours) and not IA (storage costs more
   there).
2. "Unknown or changing access pattern, no manual work" — Intelligent-Tiering, not a
   lifecycle rule: a rule requires knowing the timing up front.
3. "Protection against deletion mandated by regulation, no one can override it" —
   Object Lock in Compliance mode. Governance fits when a bypass capability is needed.
4. "Files need to act as a network drive for multiple servers" — that's not S3, it's
   EFS or FSx.
5. "Speed up bulk uploads from remote offices" — Transfer Acceleration or multipart;
   if the network is weak and the volume is hundreds of TB — Snowball.
6. "Data sits in S3, need SQL analytics without moving it" — Athena; for constant
   heavy analytics — Redshift.
7. "A web application in an external account needs access to one specific object for
   an hour" — presigned URL, not a public bucket and not an IAM user.
8. Any phrasing of "bucket is public" points to Block Public Access, not to editing
   the ACL.

## Numbers to remember

- minimum storage duration: Standard-IA and One Zone-IA — 30 days, Glacier Instant
  Retrieval — 90, Glacier Flexible Retrieval — 90, Deep Archive — 180;
- minimum billable object size in those classes — 128 KB;
- retrieval from Glacier Flexible Retrieval: Expedited 1–5 minutes, Standard 3–5
  hours, Bulk 5–12 hours; from Deep Archive — 12 hours, up to 48 in Bulk mode;
- Glacier Instant Retrieval returns objects in milliseconds, same as Standard-IA;
- an object ranges from 0 bytes to 5 TB, a single PUT up to 5 GB, beyond that only
  multipart (up to 10,000 parts);
- performance per prefix: 3,500 write requests and 5,500 read requests per second, any
  number of prefixes;
- durability 99.999999999%, Standard availability 99.99%, One Zone-IA 99.5%;
- transition to Standard-IA via a lifecycle rule is possible no earlier than 30 days
  after object creation.

## Mini practicum

**1.** An archive is needed quarterly, retrieval within a few hours is acceptable,
storage cost must be minimal.
→ Glacier Flexible Retrieval. Deep Archive is cheaper but takes 12 hours, while IA
costs more to store.

**2.** The file access pattern is unknown in advance and keeps changing; no manual
rules wanted.
→ Intelligent-Tiering: the class moves objects between tiers automatically, with no
retrieval penalty.

**3.** A regulator requires that files can't be modified or deleted for five years,
including by an administrator with full permissions.
→ Object Lock in Compliance mode. Governance can be bypassed by a user with a special
permission.

**4.** An application in an external account needs one-hour access to a single
object.
→ presigned URL. Neither a public bucket nor a dedicated IAM user is needed.
