# SAA-C03 Trainer

Офлайн-тренажёр и учебник для экзамена AWS Certified Solutions Architect – Associate
(SAA-C03): 1019 вопросов с проведённым аудитом ключей, 22 главы конспектов и приложение
о разметке доменов, письменные разборы ответов, режим экзамена по весам blueprint. Чистые HTML/CSS/JS без сборщика, CDN и серверной части —
открывается прямо с файловой системы, с сайта или как приложение для Android.

> Банк вопросов получен из стороннего дампа и опубликован только для личной
> подготовки. `robots.txt` в сборке запрещает индексацию; права на содержимое дампа
> мне не принадлежат.

Рабочий сайт: **https://saa.maks.top** — собирается и выкладывается
[`.github/workflows/pages.yml`](.github/workflows/pages.yml) при каждом пуше в `main`.

## Запуск

```bash
python3 -m http.server 8101   # затем http://localhost:8101/web/
```

Либо просто открыть `web/index.html` в браузере: всё работает по `file://`, прогресс
сохраняется в localStorage и переживает перезагрузку.

## Что умеет

- **Тренировка** — фильтры по домену, сервису и статусу (не отвеченные, ошибочные,
  решённые верно, отмеченные, с исправленным ключом, спорные), поиск по тексту и переход
  к вопросу по номеру, мгновенный разбор, горячие клавиши `1…6`, `Enter`, `→`, `f`.
- **Экзамен** — 65 вопросов по весам blueprint (SEC 20, RES 17, PERF 15, COST 13),
  таймер 130 минут, попытку можно продолжить после закрытия вкладки, результат по
  доменам и полный разбор; любую прошлую попытку можно открыть из истории и разобрать
  заново.
- **Учебник** — 22 главы по-русски плюс приложение о том, как определяется домен
  вопроса; из главы один клик до её вопросов, из разбора вопроса — до нужной главы
  (связь через поле `svc`). В конце каждой главы автоматически собирается таблица
  доменов её вопросов с примерами ручных решений.
- **Разборы ответов** — разобраны все вопросы банка: видно, почему ключ именно такой,
  а под каждым неверным вариантом — почему он не подходит. У спорных вопросов показаны
  обе трактовки, а не приговор. Внутри разбора есть ссылки на родственные вопросы:
  из ответа про класс хранения один клик до почти такого же вопроса с другим ответом.
  1019 вопросов из 1019, источник — `data/explanations.json`.
- **Прозрачность аудита** — у 28 исправленных вопросов видно исходный ключ дампа и
  причину правки, у 23 спорных — альтернативу и аргумент.
- **Прогресс** — в localStorage: точность по доменам, таблица слабых тем (сервисы
  отсортированы по вашей точности, клик по строке открывает тренировку по этому сервису),
  история экзаменов, экспорт и импорт JSON.
- **Офлайн** — приложение открывается прямо с файловой системы, а опубликованный сайт
  ставится как PWA: service worker заранее кладёт в кеш само приложение, банк и учебник,
  поэтому решать можно без сети. Имя кеша содержит идентификатор деплоя, так что новая
  сборка никогда не подменяется старой.
- **Приложение для Android** — та же программа в оболочке Capacitor: банк, учебник и
  разборы лежат внутри APK, аппаратная кнопка «назад» отматывает интерфейс, а разрешений
  приложение не просит вообще, включая `INTERNET`. Подробности —
  [mobile/README.md](mobile/README.md).

## Структура

```
data/       банк, оверлей аудита, ручная разметка доменов, разборы, метаданные, главы
docs/       22 главы учебника в markdown и приложение appendix-domains.md
images/     13 картинок-экспонатов к 7 вопросам
web/        приложение: index.html, css/, js/, сгенерированные data/*.js,
            sw.js и manifest для офлайн-режима
mobile/     оболочка Capacitor для Android (www/ и node_modules/ генерируются)
scripts/    пайплайн данных, сборка сайта и сборка приложения
```

## Пайплайн

```bash
python3 scripts/parse.py           # raw.txt -> data/build/questions.parsed.json
python3 scripts/classify.py        # домены, сервисы, признак мультиответа
python3 scripts/apply-audit.py     # оверлей аудита -> data/questions.json
python3 scripts/build-theory.py    # docs/*.md -> data/theory/*.json
python3 scripts/build-web-data.py  # json -> web/data/*.js
python3 scripts/validate.py        # проверка критериев готовности
```

Разметка домена: 672 вопроса определены сильными маркерами в тексте, остальные 347
прочитаны и размечены вручную — они лежат в `data/dom-overrides.json` вместе с коротким
обоснованием (`dom_why`, видно в разборе вопроса). Вопросов с доменом «по умолчанию»
или по слабым маркерам в банке не осталось, `validate.py` это проверяет. Счётчики
доменов в `meta.json` пересчитывает пайплайн.

Сборка воспроизводима: на чистом клоне пайплайн собирает `data/questions.json`
побайтово тем же самым. Результаты аудита лежат отдельно в `overlay.json`, поэтому
новый дамп можно перепарсить, не потеряв правки.

## Проверки перед пушем

```bash
bash scripts/check.sh      # около 4 секунд
```

Скрипт повторяет то, что делает CI: пайплайн данных и `validate.py`, сверку
закоммиченных артефактов со свежей пересборкой, `node --check` по javascript приложения,
сборку сайта и сборку веб-части приложения **из каталога `mobile/`, ровно как её
вызывает CI** — именно на этом различии однажды упал workflow APK. Последний шаг
работает и на чистом клоне, где `mobile/node_modules` ещё нет: там он проверяет
копирование и пути и сообщает, что рантайм Capacitor не установлен, вместо того чтобы
молча пропуститься.

Локальные настройки git с клоном не приезжают, поэтому хук `pre-push` до первого
включения не работает — на каждом клоне его включают один раз:

```bash
bash scripts/setup.sh      # ставит core.hooksPath = .githooks
```

`check.sh` предупреждает, если хук не подключён. Обойти в исключительном случае:
`git push --no-verify`. Тот же скрипт крутится в CI как workflow «Проверки» на каждый
push и pull request, поэтому клон без хука тоже прикрыт — просто на один круг позже.

Регенерация сырого текста из PDF:

```bash
pdftotext -layout SAA-C03-1019QA.pdf data/raw.txt
```

## Главы учебника

S3 · EC2 · Балансировщики и Auto Scaling · VPC · IAM · Шифрование и KMS · RDS ·
Aurora · DynamoDB · Lambda · Интеграция (SQS, SNS, EventBridge, Step Functions) ·
EFS и FSx · EBS · Гибридные подключения · Перенос данных · CloudFront и edge ·
Route 53 · Контейнеры · Аналитика · Защита периметра · Управление · Стоимость

В каждой главе обязательны блоки «что спрашивают на экзамене», сравнительные таблицы
похожих сервисов, «числа, которые надо помнить», мини-практикум и ссылки на конкретные
вопросы банка, разобранные при аудите.

## Сборка сайта

Workflow пересобирает банк и учебник из исходников, прогоняет `validate.py` и только
потом запускает `scripts/build-site.sh`. Скрипт складывает каталог `site/`: содержимое
`web/` в корень, `images/exhibits/` рядом, `config.js` с путём к картинкам для корневой
раскладки, идентификатор коммита в имя кеша service worker, `CNAME`, `.nojekyll` и
`robots.txt` с запретом индексации. Руками на сайт ничего не копируется, упавшая
проверка роняет деплой. Тот же скрипт собирает сайт локально:

```bash
bash scripts/build-site.sh site local-check
```

## Приложение для Android

```bash
cd mobile && npm ci && npm run apk
```

`scripts/build-app.sh` собирает веб-часть для оболочки, `npx cap sync android` кладёт её
в проект, Gradle выдаёт `mobile/android/app/build/outputs/apk/debug/app-debug.apk`
(около 6 МБ, без разрешений). Подписанная сборка и подробности —
в [mobile/README.md](mobile/README.md).

## Домены банка

| Домен | Вопросов | Вес blueprint | В экзамене |
|---|--:|--:|--:|
| SEC — Design Secure Architectures | 324 | 30% | 20 |
| RES — Design Resilient Architectures | 209 | 26% | 17 |
| PERF — Design High-Performing Architectures | 259 | 24% | 15 |
| COST — Design Cost-Optimized Architectures | 227 | 20% | 13 |

Доли банка не совпадают с весами экзамена намеренно: выборка режима «Экзамен» строится
по blueprint, а не пропорционально банку.

## Аудит банка

28 исправленных ключей, 23 спорных, вопросов с низкой уверенностью не осталось,
3 дефекта исходного PDF, 2 вопроса с пометкой о неточной или устаревшей формулировке,
7 вопросов с экспонатами. Письменные разборы: все 1019 вопросов — у каждого обоснован
ключ и разобран каждый неверный вариант. Полные формулировки аудита —
в [data/audit-log.md](data/audit-log.md).
